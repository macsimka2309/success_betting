# Единый диспетчер API/Fonbet

Контракт: `specs/оповещения-по-общим-live-данным.md`, миграция 027.
Новый код не открывает .env: systemd передаёт прежнее окружение через EnvironmentFile.
Адресат и SOCKS-транспорт те же. Токен в curl передаётся stdin, исключения обезличены.

Перед выкладкой сохранить схему и версии затронутых файлов. Под блокировками
`/opt/apps/football-collector/logs/.live-alerts.lock` и
`/opt/apps/fonbet-sync-pilot/output/live/collect.lock` применить только 027 в
транзакции с lock_timeout=5s, зарегистрировать версию. Не запускать `migrate up`
всех версий вслепую. 027 сначала создаёт выключенный feature flag.

Файлы API: `alert_dispatch.py`, `alert_rules.py`, `live_context.py`,
`live_statistics.py`, `live_alerts.py` из `src/jobs`.
Файлы Fonbet: `collect.cjs`, `store.py` из `tools/fonbet_live`.
Установить `football-alert-dispatch.service` и `.timer`.

Проверить запуск `python -m src.jobs.alert_dispatch --dry-run` с окружением службы.
Он выполняет оценку в rollback-only транзакции; сообщений и очереди не оставляет.
Первые актуальные контексты появятся при очередном сборе источников. В одной
транзакции установить `live_alert_dispatch_config.enabled=true`; API-процесс
после сохранения срезов прекращает прямую отправку. После этого включить таймер.

Команды состояния:

```sh
systemctl status football-alert-dispatch.timer football-alert-dispatch.service
journalctl -u football-alert-dispatch.service -n 30
```

Читать только безопасные счётчики outbox и timestamps. Исторические срезы не
рассылаются. Uncertain требует проверки доставки; автоматически возвращать его
в pending запрещено. Возвращённый message_id сохраняется в outbox. При API-ID
та же карточка попадает в прежнюю live_alerts_sent для работы кнопок бота.

Откат: остановить новый таймер и дождаться службы, установить enabled=false.
Сохранить новый совместимый `_already_sent` и live_context.py: API-путь учитывает
как старую таблицу отправок, так и sent/uncertain идентичности обоих источников.
Fonbet-сбор и matcher остаются включены; подтверждение поздней связи блокирует
повтор и в API-пути. Полное восстановление старых файлов без этой защиты требует
отдельной синхронизации памяти. Таблицы/срезы и очередь не удалять.

Проверки перед выкладкой: 199 targeted pytest (42 dispatcher) + 8 браузерных тестов; полный
связанный прогон — 279 pass и 2 существовавших ранее расхождения legacy favorite,
подтверждённых повтором без новой логики. Миграция 027 up/down проверена на
отдельном PostgreSQL, рабочие данные при тестировании не использовались.

## Среднее число голов в уведомлениях

Для этого изменения выкладываются вместе `league_goals.py`, `alert_dispatch.py`,
`live_alerts.py` и `signal_reminders.py` из `src/jobs`. Расчёт использует уже
имеющиеся поля `fixtures`, `league_seasons`, `live_match_statistics_75` и
`fonbet_competition_aliases`. Нового таймера, миграции и сетевого сбора для
показателя не требуется.

Среднее считается в пределах сезона по подтверждённым счетам основного времени.
Число матчей видно рядом со средним. «Нет данных» означает отсутствие
подтверждённой лиги или сезона либо пригодных результатов. В едином диспетчере
рассчитанное значение сохраняется в `live_alert_outbox.payload.league_goals`
вместе с сообщением и используется в напоминании. Ни одно значение среднего
не отменяет отправку. [Замер покрытия на исторической очереди](../reports/league-goals-coverage-2026-11-24.md)
