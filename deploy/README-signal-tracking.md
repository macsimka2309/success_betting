# Выпуск напоминаний и голов после первого сигнала

Текущий выпуск охватывает локальные миграции 030–036, однократное напоминание и отдельный worker голов Fonbet. Для установки требуется отдельный запрос на production-выпуск.

## Проверки перед выпуском

1. Сверить Git revision и diff локального кода и сервера. Рабочее дерево содержит изменения других задач; не включать их автоматически в этот выпуск и не сбрасывать их. Выделить reviewable commit с файлами этой функции и проверить зависимость от текущего unified dispatcher 027, snapshot normalization 028 и freebet 029.
2. Проверить статус существующих таймеров и сохранить его для восстановления. Не читать `.env`, ключи и browser profile; команды приложения получают уже настроенное окружение службы.
3. Сверить согласованный набор модулей диспетчера, штатного сбора live и worker Fonbet. Исправления девятого раунда находятся в `signal_goal_store.py`.
4. Сверить миграции 030–036 с фактическим registry. Миграцию `036_signal_poll_decisions.sql` установить до запуска сборщиков и диспетчера с новым кодом. При переходе с 035 открытые API-напоминания получают однозначно восстановленные пары из сохранённого архива в пределах своего окна. Исправления девятого раунда используют схему 036.

## Установка — только по отдельному запросу на production

1. Приостановить штатный сбор live обоих источников, диспетчер Telegram, results worker и связанные фоновые задания на согласованное короткое окно. Зафиксировать их исходное состояние и подготовить восстановление перед остановкой.
2. Установить проверенную версию Python/Node кода. В football-collector нужны Python-модули и `deploy/run_fonbet_goals.sh`. В существующий browser mount `/opt/apps/fonbet-sync-pilot/live` положить согласованный набор `timeline.cjs`, `collect.cjs`, `dom.cjs`, `memory.cjs`, `store.py`, `match_clock.py`; runtime не требует нового браузера или профиля.
3. Применить новые миграции через существующий registry, используя уже предоставленный `DATABASE_URL`, не печатая его и не открывая `.env`:

```python
import os
import psycopg
from src.db.migrate import run_up
with psycopg.connect(os.environ['DATABASE_URL'], autocommit=True) as conn:
    run_up(conn)
```

4. На время установки остановить результаты версии 1, если служба была установлена. Версия 2 закрывает ожидания версии 1 с причиной `policy_changed` и сохраняет историю. Установить согласованную версию Python и Node, затем `football-signal-results.service/.timer`. Wrapper передаёт URL, день сигнала и этап `live` или `result`. До включения проверить unit-файлы на Linux через `systemd-analyze verify`. Таймер вызывает worker каждую минуту на секунде 45. Флаг `--scheduled` допускает браузерное чтение в промежуточные минуты лишь для концовки Fonbet и обработки выхода из неё. Штатный интервал остальных этапов составляет пять минут.
5. Восстановить все ранее активные сборщики/таймеры. Не оставлять их выключенными при ошибке установки. Проверить выход службы и свежесть sports export; пустой цикл подтверждает запуск, но не успешное чтение статистики реального матча.
6. Включать функции раздельно только для новых первых оповещений:

```python
from datetime import datetime, timezone
from src.jobs.signal_tracking import configure
# Внутри уже настроенного psycopg connection/transaction:
configure(conn, tracking=True, reminders=False, now=datetime.now(timezone.utc))
# После проверки tracking и очереди разрешить reminder для следующих первых отправок:
configure(conn, tracking=True, reminders=True, now=datetime.now(timezone.utc))
```

`activated_at` сохраняется при повторном включении; feature_version записывается в новый сигнал. Уже отправленные сообщения не backfill-ятся, `sent_at` исходного outbox не сбрасывается. `goals_enabled` фиксируется при первой отправке: позднее включение tracking не подключает старые сигналы.

7. Включить новый results timer и контролировать `scripts/diagnostics/signal_tracking_status.sql`, `live_signal_check_attempts` и журнал `football-signal-results.service`. Проверить первый реальный новый сигнал, единственный reminder, первый ended result, источник/полноту. Не отправлять искусственные Telegram-сообщения ради проверки. Наблюдения собираются обычными заданиями.

## Поведение и ограничения

- Первое определимое решение `half_pressure` фиксируется по архиву опросов исходного источника. Отрицательное решение закрывает ожидание. Перед доставкой положительный триггер проверяется по свежим штатным данным в окне 65–75. Ожидание ограничено 20 минутами. Успешная или неопределённая доставка завершает очередь повтора.
- Целевые запросы после сигнала выполняются только для Fonbet. С 89-й минуты читается «Ход матча» один раз на минутный слот, включая добавленное время. При недоступной карточке остаётся последнее наблюдение, а следующие проверки проходят в штатном цикле. Лимит составляет одну браузерную попытку за запуск. Используются общие блокировки, бюджет браузера 50 секунд и действующий лимит памяти.
- Первичная загрузка назначается в пределах часа после явного конца основного времени. Послематчевый этап включает T+24 и до семи дополнительных фактических проверок. При внутреннем переносе оператор видит `result_due_at`, `next_attempt_at`, `result_wait` и причину переноса. После пяти минут ожидания от исходного срока готовая просроченная проверка получает приоритет на штатном цикле. Фактические сетевые ошибки учитываются как попытки.
- Полнота определяется по последовательности событий и отдельному счёту первого и второго таймов. Сохранённый live-снимок проверяется на расхождение при недоступном архивном таймлайне. Статус `incomplete_final` сохраняет найденные голы. Голы с неопределённым порядком относительно сигнала доступны отдельно.

## Откат функциональности

Выключить оба флага через `configure(conn, tracking=False, reminders=False, now=...)`, остановить **только новый** results timer. Отменить waiting/retry reminders с причиной operator_disabled, сохранив sent/uncertain и весь аудит. Оставить старые сборщики/таймеры включёнными и проверить их фактическое состояние. Сохранить новые таблицы и события: не выполнять destructive down в production.

Старый exporter совместим с дополнительными nullable полями context. При откате кода сначала выключить функции и оставить схему с накопленными наблюдениями. Down 036–030 используется для одноразовой тестовой установки в обратном порядке зависимостей.

## Приёмка исправлений после review

Сценарии раундов 3–9 входят в `tests/test_signal_reminders.py`, `tests/test_signal_results.py` и `tests/test_signal_goal_store.py`. Для API проверить переход 035 → 036, отклонённую пару из снимка 75 и ожидание при дубликате или несовместимых командах, включая 76-ю минуту и FT. Проверить доставку или закрытие при последующем подтверждённом контексте. Для Fonbet проверить сохранение типа и ID пенальти после неполного ответа, отдельные ID обоих голов после финального протокола и сохранение архивного ID и ревизии при повторе после объединения алиасов. Проверить получение просроченной задачей штатного слота. Для завершённого матча используется обезличенная разметка «Завершенные» с подтверждённым ID. Для полноты нужен отдельный счёт основного времени.

Для порядка статусов Fonbet проверить запоздавшие `FT` и `ABD` после подтверждённого `2H` в обоих направлениях между браузером и штатным опросом. Повтор по связанному событию остаётся в ожидании до пригодного статуса либо истечения срока. После применения протокола старый `ABD` сохраняется в аудите с причиной `superseded_observation`, а послематчевая сверка продолжается. Проверки входят в `tests/test_signal_results.py` и `tests/test_signal_reminders.py`. [Изолированные воспроизведения](../reports/signal-tracking-review-round-10-2026-11-20/repro_cases.py)

Для закрытия окна повтора проверить штатный положительный снимок на 74-й минуте и более позднюю браузерную отметку 76 того же события. Ожидание должно закрыться как `outside_window` с нулём попыток отправки и сохранённым `first_decision`. Проверка также выполняется перед отправкой для связанного сигнала API-Football. Дополнительный запрос к Fonbet в диспетчере не требуется.

Сверить readiness тесты очереди, лимит ожидания и общий дедлайн Telegram. В диагностике должны быть видны источник первого сообщения, фаза, последняя минута, причина переноса и оставшиеся проверки. Прогон на реальной карточке после выпуска должен подтвердить чтение в 89, 90+N, явный конец, а также сопоставимость счёта из «Завершенных». Локальная проверка использует обезличенную спортивную разметку и моделируемые ответы.
