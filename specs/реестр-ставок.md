# Спецификация: реестр ставок в Telegram-боте

Основание: запрос владельца (16.10.2026). Опирается на `specs/онлайн-оповещения.md`
(оповещения и таблица `live_alerts_sent`), `docs/03-модель-данных.md`,
`docs/05-безопасность.md`, бота `@goals_predict_bot` (репозиторий `bot_bet`,
туннель до 45.133.19.61).

Статус: **на согласовании**. Реализация не начата. Допущения, которые нужно
подтвердить, — в разделе «Открытые вопросы».

## Цель

Владелец получает оповещение, делает ставку и вносит её в бота за три шага. Система
сама после матча узнаёт счёт, считает результат ставки и показывает сводку по дням и
месяцам.

## Пользовательские сценарии

1. Приходит оповещение с номером («ID: 17»). Владелец нажимает «Внести событие»,
   вводит 17, выбирает рынок, вводит линию и коэффициент. Ставка записана в реестр.
2. После матча без участия владельца ставка получает результат и прибыль.
3. Владелец нажимает «Показать результат», выбирает «По дням» или «По месяцам» и
   получает таблицу.

## Определения

| Термин | Смысл |
|---|---|
| ТБ | тотал больше: голы обеих команд за основное время больше линии |
| ИТБ1 | индивидуальный тотал больше для хозяев (команда 1) |
| ИТБ2 | индивидуальный тотал больше для гостей (команда 2) |
| Линия | число голов, с которым сравнивается тотал (например, 2.5) |
| Основное время | 90 минут плюс добавленное, без дополнительного времени и пенальти (`score.fulltime` источника) |
| Единица | размер ставки 1 (допущение 1) |

## Идентификатор оповещения (ИД-1…ИД-3)

- ИД-1. У каждого оповещения появляется целый номер `alert_id` (1, 2, 3 …), уникальный.
- ИД-2. Номер резервируется из последовательности **до** отправки и печатается в
  сообщении первой строкой: `ID: 17`. Если отправка не удалась, номер сгорает
  (пропуск в нумерации допустим); при успехе строка пишется в `live_alerts_sent`
  с этим номером.
- ИД-3. В таблицу `live_alerts_sent` добавляется колонка `alert_id` (миграция).

## Диалог с ботом

Меню (постоянная клавиатура внизу): **«Внести событие»**, **«Показать результат»**.
В любой момент команда `/cancel` или кнопка «Отмена» сбрасывает диалог.

### Внести событие

| Шаг | Бот говорит | Ввод | Проверка |
|---|---|---|---|
| 1 | «Введите ID оповещения» | целое число | оповещение с таким номером есть; иначе «Такого ID нет», повтор |
| 2 | показывает матч («Home — Away, ID 17») и кнопки **ТБ / ИТБ1 / ИТБ2** | нажатие кнопки | — |
| 3 | «Введите число (линия), например 2.5» | число с точкой или запятой | кратно 0.25, от 0.25 до 20 |
| 4 | «Введите коэффициент» | число с точкой или запятой | больше 1.0, не больше 1000 |
| 5 | «Записано: № ставки, матч, рынок, линия, кф» | — | запись в реестр |

При ошибке ввода бот объясняет формат и просит повторить тот же шаг. Состояние диалога
хранится в базе, поэтому перезапуск бота не теряет начатый ввод.

### Показать результат

Кнопки **«По дням»** и **«По месяцам»**. Ответ — таблица в моноширинном шрифте:

| Период | Ставок | Результат |
|---|---:|---:|
| 2026-10-16 | 3 | +1.45 |
| 2026-10-15 | 2 | -2.00 |
| Итого | 5 | -0.55 |

«По дням» — последние 31 день, «По месяцам» — последние 12 месяцев, новые сверху.
«Ставок» — все внесённые за период (в том числе ещё не рассчитанные), «Результат» — сумма
прибыли по рассчитанным в единицах. Под таблицей строка «Не рассчитано: N», если такие есть.
Период определяется по дате внесения ставки по Москве (допущение 2).

## Реестр: данные

Новая таблица `bets` (миграция):

| Поле | Тип | Описание |
|---|---|---|
| bet_id | BIGINT, identity, PK | номер ставки |
| alert_id | INTEGER, FK → `live_alerts_sent(alert_id)` | оповещение |
| fixture_id | INTEGER NOT NULL | матч (берётся из оповещения) |
| market | TEXT, `CHECK IN ('TB','ITB1','ITB2')` | рынок |
| line | NUMERIC(5,2) | линия |
| odds | NUMERIC(7,3) | коэффициент |
| stake | NUMERIC(10,2) NOT NULL DEFAULT 1 | размер ставки в единицах |
| created_at | TIMESTAMPTZ NOT NULL DEFAULT now() | когда внесена |
| status | TEXT NOT NULL DEFAULT 'open' | `open`, `won`, `half_won`, `push`, `half_lost`, `lost`, `void` |
| goals_home, goals_away | SMALLINT | счёт основного времени на момент расчёта |
| settled_at | TIMESTAMPTZ | когда рассчитана |
| profit | NUMERIC(10,3) | прибыль в единицах |

Индексы: `(status)`, `(created_at)`, `(fixture_id)`. Несколько ставок по одному
оповещению допустимы (разные рынки и линии).

Таблица `bot_dialogs`: `chat_id BIGINT PK`, `step TEXT`, `payload JSONB`, `updated_at`.

## Расчёт результата (РС-1…РС-6)

- РС-1. Расчёт запускается отдельным заданием по расписанию. Берёт открытые ставки и
  запрашивает матчи `fixtures?ids=…` (до 20 в запросе).
- РС-2. Матч со статусом `FT`, `AET` или `PEN` рассчитывается по `score.fulltime`.
  Статусы отмены (`PST`, `CANC`, `ABD`, `AWD`, `WO`) дают результат `void`, прибыль 0.
  Остальные статусы пропускаются до следующего запуска.
- РС-3. Сравниваемое число: ТБ — сумма голов, ИТБ1 — голы хозяев, ИТБ2 — голы гостей.
- РС-4. Для линий, кратных 0.5: число больше линии — `won`, равно линии — `push`, меньше — `lost`.
  Для четвертных линий (x.25, x.75) ставка делится пополам на две соседние линии
  (2.25 → 2.0 и 2.5, 2.75 → 2.5 и 3.0): итог `won`, `half_won`, `half_lost` или `lost`.
- РС-5. Прибыль в единицах при ставке `s` и коэффициенте `k`: `won` — `s·(k−1)`, `half_won` —
  `s·(k−1)/2`, `push` и `void` — 0, `half_lost` — `−s/2`, `lost` — `−s`.
- РС-6. Если счёта нет (поле пустое у завершённого матча), ставка остаётся открытой, расчёт
  повторяется; после 48 часов без счёта владельцу уходит сообщение «не удалось рассчитать
  ставку №N».

## Расписание и бюджет

- Бот работает постоянной службой (опрос обновлений Telegram с ожиданием до 30 секунд) на
  сервере сбора, через тот же SOCKS-туннель, что и оповещения.
- Расчёт: каждые 30 минут. Запросов к API нет, если открытых ставок нет. Верхний потолок
  5 запросов на запуск; затраты берутся из резерва 300 запросов в сутки на оповещения
  (фактический расход оповещений сейчас около 100–250), общий лимит не меняется.

## Безопасность

- Бот отвечает **только** владельцу: идентификатор чата входящего сообщения сравнивается
  с `TELEGRAM_CHAT_ID`; сообщения других чатов игнорируются без ответа, факт пишется
  в журнал без текста.
- Токен только в `.env`, в журналы и ответы не попадает.
- Ввод проверяется по формату и диапазонам; все запросы к базе параметризованы.
- Разрешённые типы обновлений: сообщения и нажатия кнопок. Вебхука нет (бот забирает обновления сам).

## Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Ввод не число, запятая вместо точки | запятая принимается, нечисло — подсказка формата и повтор шага |
| ID не найден | сообщение и повтор шага 1 |
| Линия не кратна 0.25 | сообщение и повтор шага 3 |
| Коэффициент ≤ 1 | сообщение и повтор шага 4 |
| Бот перезапущен посреди диалога | диалог продолжается с сохранённого шага |
| Нажатие кнопки без активного диалога | подсказка «Начните с меню» |
| Telegram или туннель недоступны | бот повторяет опрос с паузой, ставки не теряются |
| Матч перенесён | ставка остаётся открытой до `void` по статусу или 48 часов |
| Несколько ставок на одно оповещение | допустимы |
| Старое оповещение | ставка допустима; расчёт произойдёт при ближайшем запуске |

## Критерии приёмки

| № | Критерий |
|---|---|
| АП-1 | Каждое новое оповещение содержит ID, он совпадает со строкой в `live_alerts_sent` |
| АП-2 | Полный диалог из 5 шагов создаёт одну строку в `bets` с верными значениями |
| АП-3 | Ввод с запятой принимается; неверные значения на каждом шаге не ломают диалог |
| АП-4 | Сообщения из чужого чата не меняют данные и не получают ответа |
| АП-5 | Расчёт верен на таблице случаев: ТБ/ИТБ1/ИТБ2, линии 2.0/2.25/2.5/2.75, счёт на границах, `void` |
| АП-6 | Повторный запуск расчёта не меняет уже рассчитанные ставки |
| АП-7 | Отчёт «по дням» и «по месяцам» совпадает с ручным подсчётом на тестовых данных, итоговая строка верна |
| АП-8 | Перезапуск бота посреди диалога не теряет шаг |
| АП-9 | Миграции применяются и откатываются на копии базы |

## Тестовые сценарии

Основной: полный диалог, расчёт, отчёт. Ошибки: текст вместо числа, пустой ввод, ID из
чужого диапазона, линия 2.3, коэффициент 1.0. Граничные: линия 0.25 и 20, коэффициент
1.001 и 1000, счёт, равный линии (`push`), четвертные линии, ставка на уже закончившийся
матч, матч без счёта. Права: чужой чат. Идемпотентность: повторный расчёт, повторная
доставка того же обновления Telegram (по `update_id`). Устойчивость: рестарт посреди
диалога, обрыв туннеля. Безопасность: токен не в журнале.

## Открытые вопросы

1. **Что за «число» на шаге 3 и каков размер ставки.** Допущение: число — линия
   (например, 2.5), размер ставки всегда 1 единица, финансовый результат считается в
   единицах (выигрыш `k−1`, проигрыш `−1`). Если нужен ввод суммы ставки отдельным шагом,
   поле `stake` уже заложено, добавится один шаг диалога.
2. **По какой дате группировать отчёт:** по дате внесения ставки по Москве (допущение) или по
   дате матча.
3. **Что считать результатом при дополнительном времени:** допущение — только основное
   время (90 минут плюс добавленное), как у обычных рынков тотала.
4. **Где живёт код:** допущение — в репозитории `success_betting` (рядом с базой и
   клиентом API); транспорт Telegram повторяет `bot_bet`.
