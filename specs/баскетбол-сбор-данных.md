# Спецификация: сбор баскетбольных данных (API-Basketball)

Основание: запрос владельца (20.10.2026) — собрать данные по баскетболу для модели
предсказания тоталов, начать сразу со всех лиг. Опирается на `docs/00` (цель и
ограничения), `docs/02-архитектура.md` (ADR-2 двухстадийный сбор, ADR-3 cron, ADR-5
естественные ключи, ADR-7 миграции), `specs/ежедневный-сбор.md`,
`specs/дозагрузка-пропущенного.md` и клиент `src/api/client.py`.

Статус: **решения владельца внесены 20.10.2026, ожидает утверждения**. Выполнено только по
прямому поручению владельца: миграция 016 создала на проде схему `basketball` с пустыми
таблицами (20.10.2026). Загрузчики, расписание и cron не созданы.

## Цель

Накопить в той же базе PostgreSQL полную историю баскетбольных игр и их статистики по
всем лигам, которые отдаёт API, и каждый день пополнять её свежими играми и снимками
коэффициентов на тоталы. Данные нужны для обучения и проверки модели тоталов.

## Что подтверждено проверкой (20.10.2026)

Продукт `v1.basketball.api-sports.io`, тот же ключ `APIFOOTBALL_KEY`, план Ultra:
75 000 запросов в сутки и 450 в минуту, подписка до **20.11.2026**. Лимит отдельный от
футбольного.

- **Каталог:** 428 турниров, 3 698 пар лига-сезон (2008–2029); в 774 парах заявлена
  статистика команд, в 803 — игроков, в 103 — коэффициенты (флаги покрытия в
  `leagues`).
- **Игры:** `games?league=&season=` отдаёт все игры лиги за сезон **одним запросом**
  (NBA — около 1 400 игр). В игре: дата, стадия, площадка, статус (`FT`, `AOT` —
  овертайм, `NS` и другие), очки по четвертям, овертайм и итог.
- **Статистика команды в игре** (`games/statistics/teams?id=`): попадания, попытки
  и процент по броскам с игры, трёхочковым и штрафным; подборы; передачи; перехваты;
  блок-шоты; потери; личные фолы.
- **Статистика игроков в игре** (`games/statistics/players?id=`): минуты, очки,
  броски, подборы, передачи, признак стартового состава.
- **Прочее:** таблицы (`standings`), команды (`teams`), игроки (`players`: имя,
  позиция, возраст), справочники букмекеров (34) и рынков (245).
- **Нет:** травм, составов до игры, судей, очных встреч, агрегированной статистики
  команды. Эти эндпоинты не существуют.
- **Коэффициенты (`odds?game=`):** 6–9 букмекеров (Pinnacle, 1xBet, Bet365, Marathon
  Bet, WilliamHill, BetVictor и другие), 59 рынков, в том числе `Over/Under` на матч,
  таймы и четверти. На один рынок приходится лесенка линий (десятки значений
  `Over x`/`Under x`).
- **Коэффициенты не возвращаются задним числом.** Они есть у предстоящих игр и у игры,
  сыгранной 2–3 дня назад (17.10 при проверке 20.10); у игр 16.10 и раньше, а также
  у всего сезона 2025-26 ответ пустой. Историю линий можно накопить только своими
  снимками, начиная с момента запуска.
- **Дыры в данных:** в NBA с января 2026 в статистике команды нет подборов в нападении
  и защите и личных фолов (до января есть; сезоны 2012–2019 заполнены полностью,
  в 2012-13 нет перехватов).

## Пользовательские сценарии

1. Исследователь строит выборку NBA или Евролиги за любые сезоны: игры, четверти,
   тотал, темп, броски, подборы, потери.
2. Исследователь сравнивает предсказанный тотал с рыночной линией на момент игры
   (снимки накоплены).
3. Модель каждый день получает свежие игры и статистику без ручных действий.
4. Владелец видит, по каким лигам и сезонам данные собраны полностью.

## Границы

**Входит:** справочники лиг, команд и игроков; игры; статистика команд и игроков в игре;
снимки коэффициентов на тоталы; ежедневное пополнение; историческая загрузка по всем
лигам; журнал запусков и отчёт о полноте.

**Не входит:** признаки и модель (это «Обработка данных» и «Модели»); оповещения;
живые игры в реальном времени; хранение всех 59 рынков.

## Функциональные требования

| № | Требование |
|---|---|
| БС-1 | Данные хранятся в той же БД `football`, в **отдельной схеме PostgreSQL `basketball`** (футбольные таблицы в схеме `public` и их читатели не меняются). |
| БС-2 | Каталог: лиги, сезоны с флагами покрытия, команды — обновляются раз в неделю вместе с каталогом лиг футбола. |
| БС-3 | Игры: для каждой пары лига-сезон загружается список игр одним запросом; активные сезоны (идущие и недавно закончившиеся) обновляются ежедневно, завершённые — один раз. |
| БС-4 | Статистика команд и игроков загружается для завершённых игр **всех лиг** (по флагам покрытия и по факту, см. объёмы); два запроса на игру; состояние хранится по аналогии с `fixture_fetch_state`, максимум 3 попытки. |
| БС-5 | Историческая загрузка идёт по **всем лигам сразу**, **по месяцам от свежих к старым**: очередь упорядочена по месяцу даты игры (все лиги вперемешку), нижняя граница — **сезон 2020** (владелец: статистика нужна с 2020 года). Бюджет — отдельный лимит баскетбола. |
| БС-6 | Снимки коэффициентов: **два раза в сутки** для предстоящих игр лиг с заявленным покрытием коэффициентов; сохраняются только **Pinnacle и 1xBet** и рынки: `Over/Under` на матч, `Over/Under` по периодам (1-й и 2-й тайм, четверти 1–4), победитель матча `Home/Away` (П1/П2). |
| БС-7 | Повторный запуск безопасен: запись по ключу API (`game_id`, `team_id`, `league_id`, `player_id`) через `ON CONFLICT`, дубли невозможны. |
| БС-8 | Каждый шаг пишет строку в `collection_runs` с префиксом `bb_` в имени шага (журнал общий с футболом). |
| БС-9 | Отсутствующее поле (подборы, фолы) хранится как `NULL`, не как ноль; пустой ответ источника не считается ошибкой. |
| БС-11 | Статистика игроков хранится по **всем лигам**, где источник её отдаёт. |
| БС-10 | Отчёт о полноте по лигам и сезонам: сколько игр, у скольких есть статистика, есть ли коэффициенты. |

## Бизнес-правила

- Значения хранятся как отдал источник; производные (владения, темп, эффективность,
  второй тайм как разница) считаются в запросах и витринах «Обработки данных»
  (ADR-4, ADR-8).
- Итог игры с овертаймом хранится как есть, овертайм — отдельным полем; тотал
  «основное время» (четыре четверти) выводится из четвертей.
- Сезоны в API бывают двух видов ключа: `2025-2026` и `2025` (Евролига — `2025`).
  Идентификатор сезона хранится как есть, без нормализации.
- Минуты хранятся числом секунд (`"32:17"` → 1937), проценты не хранятся (их считает
  запрос).
- Лиги-женские, молодёжные и кубки включаются в общую загрузку; отбор по ним делается
  при построении признаков.

## Данные

Все таблицы в схеме `basketball` (названия без префикса); ключи — естественные идентификаторы
источника:

| Таблица | Ключ | Содержимое |
|---|---|---|
| `basketball.leagues` | `league_id` | название, тип, страна |
| `basketball.league_seasons` | `(league_id, season)` | даты, флаги покрытия: статистика команд, игроков, коэффициенты, таблицы |
| `basketball.teams` | `team_id` | название, страна |
| `basketball.players` | `player_id` | имя, позиция |
| `basketball.games` | `game_id` | лига, сезон, дата и время UTC, стадия, статус, команды, очки по четвертям, овертайм, итог, площадка |
| `basketball.team_game_stats` | `(game_id, team_id)` | броски (попадания, попытки), трёхочковые, штрафные, подборы всего / в нападении / в защите, передачи, перехваты, блок-шоты, потери, фолы |
| `basketball.player_game_stats` | `(game_id, team_id, player_id)` | старт или скамейка, минуты, очки, броски, подборы, передачи |

| `basketball.odds_values` | `(snapshot_id, bookmaker_id, market, value)` | линия и коэффициент выбранных рынков |

Перепись прошла по всем 3 698 парам лига-сезон (3 698 запросов, ошибок доступа нет):

| Показатель | Значение |
|---|---:|
| Игр в списках всего | 519 870 |
| Завершённых игр | 491 205 |
| Пар с заявленной статистикой команд и игроков | 758 (98 313 игр, 82 372 завершённых) |
| Пар с заявленной статистикой только команд | 16 (1 254 завершённых) |

Заявленная статистика (флаги покрытия) есть почти исключительно с сезона 2023-24,
но флаги занижают реальное покрытие. Выборка по одной завершённой игре в каждой из
2 900 пар «без заявленной статистики» (20.10.2026) показала, что статистика фактически
отдаётся в **664 парах**: команд в 495, игроков в 654. Больше всего их среди сезонов
2017–2022 (например, 2020: 116 из 188, 2021: 164 из 262, 2022: 172 из 294); до 2012 года
статистики нет нигде. Выборка даёт оценку «в лиге-сезоне статистика есть», но не
гарантирует, что она есть у каждой игры.

**Оценка для окна с сезона 2020** (владелец): завершённых игр со статистикой — около
**149 642** (87 579 с заявленной и 62 063 найденных выборкой), то есть до **299 тыс.
запросов** на статистику команд и игроков, около четырёх суток лимита 75 000. Для всех
сезонов с 2008 года потолок около 980 тыс. запросов (13 суток), но до 2012 года
статистики нет, так что реально меньше.

Самые большие лиги по играм с заявленной статистикой: NBA (4 213 из 24 638 игр), B League
Япония (2 378), CBA Китай (1 528), Serie A2 Италия (1 337), B2.League Япония (1 316),
NBB Бразилия (1 198), Pro B Франция (1 163), Евролига (1 123 из 4 690).

## Бюджет запросов

Лимит баскетбола 75 000 в сутки отдельный. Первичная выкладка: каталог и списки игр —
около 3 700 запросов; статистика команд и игроков — 2 запроса на игру в лигах с
покрытием. Ежедневная работа: списки игр активных сезонов, статистика новых игр, снимки
коэффициентов. Историческая загрузка идёт на остатке и не должна выходить за
50 000 запросов в сутки, чтобы оставить запас на оповещения и срочные задачи.

Подписка действует до 20.11.2026: историю стоит загрузить за этот срок.

## Коэффициенты: состав и расписание

- **Букмекеры:** Pinnacle и 1xBet (решение владельца).
- **Рынки (названия в API):** `Over/Under` (матч), `Over/Under 1st Half`, `Over/Under 2nd Half`,
  `Over/Under 1st Qtr`, `Over/Under 2nd Qtr`, `Over/Under 3rd Qtr`, `Over/Under 4th Qtr` и
  `Home/Away` (победитель матча, П1/П2). Остальные из 59 рынков не сохраняются.
- **Лестница линий:** у `Over/Under` на букмекера приходится десяток и больше линий;
  сохраняются все линии, пришедшие в ответе.
- **Расписание:** два снимка в сутки, в 00:00 и 12:00 UTC (как у футбола); берутся игры
  со статусом `NS`, начинающиеся в ближайшие 36 часов, в лигах с заявленным покрытием
  коэффициентов. Один запрос `odds?game=` на игру.
- **Объём:** около 100–200 игр в день × 2 снимка × 2 букмекера × десятки линий ≈ сотни
  тысяч строк в сутки. Оценка места и срок хранения — после недели работы.

## Интерфейсы

- Клиент `ApiClient` с базовым адресом баскетбола (параметр базового URL, кэш в отдельном
  каталоге `cache_bb`, правило `use_cache=False` для игр и коэффициентов).
- Шаги CLI с префиксом `bb-`: каталог, игры, статистика, коэффициенты, дозагрузка,
  отчёт о полноте.
- Обёртка cron по образцу `run_collect.sh` (`flock`, проверка часового пояса).

## Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Игра без статистики (низшая лига) | не ошибка, попытка засчитана, после 3 — больше не запрашивается |
| Статистика пришла без подборов в нападении и защите | пишутся имеющиеся поля, остальные `NULL` |
| Игра перенесена или отменена | статус обновляется при очередной загрузке списка игр |
| Игра с овертаймом | овертайм хранится отдельно, итог включает его |
| Исчерпан суточный лимит | шаг завершается штатно, остаток уходит на следующий день |
| Сезон в API закрыт тарифом | запрос возвращает ошибку доступа, лига-сезон пропускается и отмечается |
| Коэффициентов у игры нет | снимок пропускается, не ошибка |
| Дубли лиги под разными ключами сезона | не склеиваются, хранятся как отдал источник |

## Безопасность

Ключ API — прежний, только в `.env` на сервере сбора, в журналы не попадает. Новых
открытых портов, пользователей и прав нет. Данные — публичная спортивная статистика.

## Критерии приёмки

| № | Критерий |
|---|---|
| АП-1 | Миграции применяются и откатываются на копии БД; футбольные таблицы не затронуты |
| АП-2 | Для лиги-сезона NBA 2023-24 загружено 1 377 игр, у завершённых есть статистика команд и игроков, итог игры равен сумме четвертей и овертайма |
| АП-3 | Повторная загрузка не меняет число строк и не создаёт дублей |
| АП-4 | Отсутствующие подборы и фолы хранятся как `NULL` |
| АП-5 | Снимки коэффициентов набираются по расписанию; для игры есть несколько снимков до её начала |
| АП-6 | Отчёт о полноте показывает пары лига-сезон без статистики при заявленном покрытии |
| АП-7 | Расход за сутки не превышает лимит баскетбольной подписки, ежедневный футбольный сбор не страдает |

## Тестовые сценарии

Основной: список игр, статистика команд и игроков, снимок коэффициентов → верные строки
и счётчики. Граничные: игра с овертаймом, игра без четвертей, пустые подборы, минуты
вида `"32:17"` и `null`, игрок без минут. Ошибки: HTTP-ошибка, `errors` в теле, закрытый
тарифом сезон, пустой `response`. Идемпотентность: двойная запись. Очередь:
игра выпадает после успеха и после 3 неудач. Бюджет: шаг останавливается на потолке.
Совместимость: футбольные запросы и тесты не меняются. Прав доступа в системе нет.

## Открытые вопросы

1. Подтвердить, что `Home/Away` без периодов достаточно (П1/П2 только на матч, без
   таймов и четвертей).
2. Подтвердить время снимков: 00:00 и 12:00 UTC (03:00 и 15:00 по Москве).
3. Хранить ли все линии лестницы `Over/Under` или только ближайшие к основной (экономия
   места, но потеря формы лестницы).
4. Допустимо ли, что в истории (до запуска) коэффициентов не будет вообще: источник их
   не отдаёт задним числом, линии копятся только с момента запуска.
