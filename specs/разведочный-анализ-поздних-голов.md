# Спецификация: разведочный перебор признаков для голов после отсечки (75')

Основание: серия запросов владельца в чате «Анализ данных» (12.10.2026) —
витрина по владению/ударам, фильтр по разрыву в счёте на 70-й минуте, доля
голов после 70-й минуты, разбивка по лигам и по ситуации в счёте. Опирается
на `docs/03-модель-данных.md` (`fixtures`, `fixture_statistics`,
`fixture_statistics_halves`, `fixture_events`, `fixture_fetch_state`) и на
правило трёх (пяти) чатов о едином информационном поле (`[[project-three-chat-split]]`).

Статус: **утверждена владельцем 13.10.2026, скорректирована 13.10.2026**
(решения — раздел «Принятые решения»). Реализация не начата.

## Цель

**Изменено 13.10.2026.** Исходная формулировка («систематически перебрать и
ранжировать по EV») заменена на целевой поиск: найти комбинации признаков, при
которых доля матчей с голом после отсечки **не ниже 0.67, в идеале ≥ 0.70**
(задано владельцем). Отсечка изменена с 70-й на **75-ю минуту** (владелец,
13.10.2026) — после просмотра распределения голов по 15-минутным интервалам:
гол в отрезке 76–90' случается в 47.45 % всех матчей базовой выборки, заметно
чаще, чем в любом другом 15-минутном отрезке матча.

Это меняет характер задачи: не «описать и ранжировать по доходности», а
«найти подвыборку(и), где истинная (не выборочная) доля достаточно высока».
Поиск по сотням/тысячам комбинаций ради пересечения высокого порога — классика
переобучения (чем экстремальнее порог, тем легче превысить его случайно на
маленькой выборке), поэтому гейтинг через доверительный интервал и
подтверждение на holdout — не формальность, а единственная защита (см. РА-12).

Коэффициенты 1.7/2.4 и ранжирование по EV остаются как **вторичная**, не
основная метрика (см. «Бизнес-правила») — целевой порог 0.67–0.70 сам по себе
даёт комфортный запас над безубыточной долей 1/1.7 ≈ 0.588, поэтому это, по
сути, тот же вопрос, поставленный жёстче. Две независимые целевые переменные
(РА-6) — гол любой команды и гол именно команды с преимуществом — остаются в
силе, поиск 0.67–0.70 ведётся по обеим параллельно.

## Границы

- **В охвате:** построение широкой витрины по всем FT-матчам с полной
  статистикой; перебор по заданной решётке порогов; поиск комбинаций,
  достигающих цели 0.67/0.70 (РА-12, основная метрика); доля исходов и EV при
  двух заданных кф как вторичная, информационная метрика; защита от
  переобучения (минимальный объём выборки, поправка на множественные
  сравнения, train/holdout по сезонам).
- **Вне охвата этой версии:** реальные live-коэффициенты (есть только два
  фиксированных числа от владельца, не калиброванная кривая), минутная
  детализация ударов (её не существует в источнике — см. «Известные
  ограничения»), автоматическое размещение ставок, скан по минуте отсечки
  (фиксируется **75** как параметр запуска, не перебирается внутри одного
  прогона; 70 сохраняется только как фиксированное значение для регрессионной
  проверки АП-4, см. «Принятые решения», п. 9).
- Это разведочный анализ исторических данных, не финансовая рекомендация и
  не готовая торговая стратегия — см. уже сделанные оговорки в переписке
  чата и `specs/проверка-ставок-новостями.md` (похожая оговорка для другого
  этапа).

## Известные ограничения (важно для интерпретации результатов)

Выяснено в этом чате при ручном анализе той же темы 12–13.10.2026, фиксирую,
чтобы не терять при реализации:

1. **В источнике нет ударов с привязкой к минуте — вообще, не только
   «неудобно».** `fixture_events` содержит только `Goal`, `Card`, `subst`,
   `Var` (docs/03). Удары существуют только как итог за матч
   (`fixture_statistics`) или за тайм (`fixture_statistics_halves`, когда
   наполнится — см. «Принятые решения», п. 1). Это значит, что ровно «удары
   команды до 70-й минуты» восстановить нельзя ни сейчас, ни после
   наполнения таймов — только приблизить.
2. **Принятое приближение (половина 2-го тайма) и его измеренная погрешность —
   теперь прямо подтверждена отдельным замером.** Решение владельца
   13.10.2026: использовать статистику **2-го тайма целиком** (46–90+) как
   приближение «состояния до отсечки», в предположении, что начало второго
   тайма похоже по игре на его конец. Два независимых измерения показывают
   одно и то же смещение:
   - по голам 2-го тайма сезонов 2021–2025 (надёжные матчи, АП-2): разбивка
     46–70 / 71–90+ даёт **48.5 % / 51.5 %** при том, что первое окно на 5
     минут длиннее (при однородности ожидалось бы 55.6 % / 44.4 %);
   - по распределению голов по 15-минутным интервалам на базовой выборке
     (131 080 матчей, задача «нарисовать график», 13.10.2026): интервал
     **76–90' — ровно окно после новой отсечки 75'** — даёт 23.18 % всех
     голов матча (ожидалось бы 16.7 % при равной интенсивности) и присутствует
     в **47.45 %** всех матчей базы, заметно больше любого другого
     15-минутного интервала.

   Предположение об однородности **эмпирически не подтверждается** дважды —
   голы (и, по всей вероятности, удары, раз они их причина) смещены к концу
   матча. Практическое следствие: статистика 2-го тайма **систематически
   переоценивает** интенсивность до отсечки, и переоценивает тем больше, чем
   больше в матче было ударов именно после отсечки — то есть ровно в тех
   матчах, где целевая переменная положительна. Это не случайный шум, а
   смещение в сторону гипотезы. Отчёт должен явно показывать обе цифры рядом
   с результатами, которые используют признак 2-го тайма.
3. **Надёжность данных о голах.** У части матчей (подтверждено с чатом
   «Выгрузка данных» 12.10.2026) `fixture_events` не содержит ни одной
   строки, хотя итоговый счёт ненулевой — либо события ещё не собраны
   (`fixture_fetch_state.events_fetched_at IS NULL`, очередь дозагрузки
   закроется ориентировочно 8–10.12.2026), либо источник для этой лиги не
   отдаёт события вовсе (`events_fetched_at` проставлен, ответ пустой).
   Единственный надёжный признак — `fixture_fetch_state.events_fetched_at
   IS NOT NULL`; без этого матчи с ненулевым счётом и без событий ложно
   считаются «гол после отсечки».
4. **Перебор по порогам — множественные сравнения, усугублено поиском
   экстремального порога.** Решётка (с учётом замен/карточек, см. п.
   «Принятые решения», 9) — не 720, а **14 400** комбинаций (6×6×5×5×4×4;
   арифметика в версии до 13.10.2026 была ошибочной — 6×6×5×5 = 900, не 720).
   Это уже много для обычного ранжирования по EV; для цели «найти ≥0.67–0.70»
   риск выше вдвойне — чем экстремальнее порог, тем легче какой-нибудь из
   14 400 (не независимых, пересекающихся) комбинаций превысить его на шуме,
   особенно при малом `n`. Поправка на множественные сравнения необходима, но
   недостаточна сама по себе (комбинации коррелируют, FDR на коррелирующих
   тестах консервативен, но не идеален) — обязательное условие — холдаут
   (см. РА-12, «Принятые решения», п. 9).
5. **Замены и карточки — корреляция, не причина.** Команда делает замену или
   получает карточку в ответ на состояние игры (отстаёт в счёте, устала),
   а не случайно. Эти признаки — такой же симптом состояния матча, как и
   сам последующий гол, а не независимая причина. Выводы по ним — ассоциация,
   не механизм «замена вызывает гол» (см. «Интерпретируемость»).

## Пользовательские сценарии

1. Владелец запускает перебор и получает таблицу: по каждой комбинации
   порогов — сколько матчей попало, доля с голом после отсечки (75'), её
   95 %-ДИ, флаг «подходит под цель 0.67/0.70» (train и holdout раздельно),
   EV на «гол» по 1.7 и на «не гол» по 2.4 как вторичную метрику.
2. Владелец сужает/расширяет решётку порогов без правки кода (конфиг или
   параметры CLI).
3. Владелец получает отдельно комбинации, подтверждённые на отложенных
   сезонах (не только на обучающей части).
4. Через 1–2 месяца, когда дозагрузка событий и таймов продвинется
   (`[[feedback_cross_chat_coordination]]`), владелец перезапускает тот же
   скрипт и сравнивает результат — повторяемость без переписывания запросов
   вручную, как это было в этом чате до сих пор.

## Функциональные требования

| № | Требование |
|---|---|
| РА-1 | Базовая выборка: FT-матчи, у которых есть `ball_possession`, `total_shots`, `shots_on_goal` по обеим командам в `fixture_statistics`. Текущий объём на проде: **132 961** матчей (проверено 12.10.2026). |
| РА-2 | Надёжность голов: матч исключается из анализа исходов, если итоговый счёт (`COALESCE(ft90_*, goals_*)`) больше нуля, а `fixture_fetch_state.events_fetched_at IS NULL` для этого `fixture_id`. Матчи 0:0 не исключаются независимо от статуса событий. |
| РА-3 | Признак «команда с преимуществом» и её статистика (владение/удары) определяется на уровне матча: берётся сторона (дом/гости) с владением строго больше порога `T_poss` из решётки; если ни одна сторона не превышает порог — матч не попадает в комбинацию с этим порогом (как и в ручном анализе ранее). |
| РА-4 | Решётка порогов — декартово произведение по осям: владение `T_poss ∈ {55,60,65,70,75,80}`, удары по воротам (`total_shots`) `T_shots ∈ {0,1,...,10}` (изменено 13.10.2026, было `{7..12}`), удары в створ `T_sog ∈ {0,1,...,10}` (изменено 13.10.2026, было `{2..6}`), ситуация в счёте на 75-й у команды с преимуществом — чистое разбиение по разнице `{проигрывает_2+, проигрывает_1, ничья, выигрывает_1, выигрывает_2+}`; замена ведущей команды `dominant_subst_window ∈ {да, нет}`, замена отстающей команды `other_subst_window ∈ {да, нет}` (см. РА-4б). Итого **14 520** комбинаций (6×11×11×5×2×2; было 3600 до расширения осей ударов). Карточки из решётки убраны. |
| РА-4а | **Фаза 1 (сейчас):** `T_poss`/`T_shots`/`T_sog` считаются по `fixture_statistics` (итог за весь матч). **Фаза 2 (после наполнения `fixture_statistics_halves`):** те же оси пересчитываются по `half=2` этой же таблицы как уточнённое приближение (см. «Известные ограничения», п. 2); обе фазы попадают в отчёт раздельно и помечены, какая использована. |
| РА-4б | **Признаки без утечки** (входят в решётку РА-4; окно изменено 13.10.2026, «Принятые решения», п. 17): `dominant_subst_window` — был ли хотя бы один `fixture_events` с `type='subst'` у команды с преимуществом по владению с минутой в окне **[60, cutoff_minute]** включительно; `other_subst_window` — то же у другой команды. Верхняя граница окна — текущая отсечка (75 по умолчанию, 70 при регрессии АП-4), не захардкожена отдельно — при смене `--cutoff` окно сдвигается вместе с ней. Карточки убраны из решётки целиком. |
| РА-5 | Минута отсечки — параметр запуска, по умолчанию **75** (изменено с 70, владелец, 13.10.2026, на основе распределения голов по 15-минутным интервалам — интервал 76–90' даёт 47.45 % матчей с голом, заметно больше соседних). Значение 70 сохраняется отдельно для регрессионной проверки АП-4. Не перебирается внутри одного прогона (РА-4). |
| РА-6 | Две независимые целевые переменные на одной решётке (РА-4): **(А) гол любой команды после отсечки** и **(Б) гол именно команды с преимуществом после отсечки**. Базовые доли на отсечке 75' (проверено на проде кодом реализации 13.10.2026, поле `total_shots`, не прокси): на выборке владение >60 %/удары ≥9/4/надёжные события, сезоны без ограничения, `n=29 399` — А = 53.09 %, Б = 41.49 %. Цифры 12-13.10.2026 (`n=26 912`, А=53.58 %, Б=42.32 %) считались старым прокси `shots_on_goal+shots_off_goal` — близки, но не те же (ДП-примечание); обе — ориентир «лифт против базовой доли», не цель сама по себе (цель — РА-12). |
| РА-7 | Для каждой комбинации и каждой целевой переменной считается: `n`, точечная оценка доли, **95 %-доверительный интервал по Уилсону**, лифт против базовой доли (РА-6), `EV_yes = share × 1.7 − 1` (для Б — кф не задан, не считается), `EV_no = (1 − share) × 2.4 − 1` (только для А), двусторонний p-value против безубыточной доли — всё как вторичные метрики рядом с РА-12. |
| РА-8 | Комбинации с `n` меньше порога не ранжируются как «кандидат». Порог — **300** (повышен с 200, см. «Известные ограничения», п. 4 и «Принятые решения», п. 9) именно для цели РА-12; для вторичных метрик (РА-7) порог 200 как раньше. |
| РА-9 | К p-value применяется поправка на множественные сравнения (Benjamini-Hochberg) по числу фактически протестированных комбинаций с `n` выше порога, отдельно для каждой из двух целевых переменных (РА-6). Поправка — необходимое, но не достаточное условие для цели РА-12 (комбинации пересекаются, тесты не независимы) — обязательно дополняется холдаутом. |
| РА-10 | Train/holdout по сезонам (изменено 13.10.2026, «Принятые решения», п. 15): train — **2018–2022**, holdout — **2023–2025**. Решётка перебирается и ранжируется только на train; **все** комбинации, прошедшие гейт РА-12 на train (не только топ-20), пересчитываются на holdout — без подгонки порогов. Сезоны 2026–2027 — отдельный блок «мониторинг». Все сезоны базы участвуют в train или holdout — пустой группы нет (была в предыдущей версии: 2018–2020). |
| РА-11 | Результат — воспроизводимый артефакт и короткий текстовый отчёт; запуск — CLI-job, повторяемый без правки кода. Результаты пишутся в БД (см. «Данные») для сравнения повторных прогонов. |
| РА-12 | **Критерий «нашли» (основная цель, добавлено 13.10.2026).** Комбинация считается **кандидатом** на train, если `n ≥ 300` и нижняя граница 95 %-ДИ Уилсона доли ≥ **0.67**; помечается **сильным кандидатом**, если точечная оценка доли ≥ **0.70**. Комбинация считается **подтверждённой**, только если на holdout (той же комбинацией, без перенастройки) `n ≥ 150` и точечная доля ≥ **0.60**, а нижняя граница ДИ holdout — не ниже **0.55**. Если ни одна комбинация не прошла оба гейта — отчёт говорит об этом прямо («по целевой переменной Х на пороге 0.67/0.70 подтверждённых кандидатов нет»), результат не форсируется. Holdout-бар (0.60/0.55) мягче train-бара (0.67) осознанно — это рекомендация автора спецификации, не требование владельца; подлежит пересмотру по факту первого прогона. |

**ДП-примечание (уточнено при реализации 13.10.2026).** В ручных выгрузках
этого чата ранее использовалось `shots_on_goal + shots_off_goal` как прокси
«ударов по воротам». В схеме есть прямое поле `total_shots` — в реализации
используется оно. Проверено на проде: поля **различаются в 83.8 % строк**
`fixture_statistics` (229 147 из 273 460), не на единицы — `total_shots`
обычно заметно **больше** суммы (пример: `total_shots=24` при
`on_goal+off_goal=16`), потому что включает блокированные удары, которых
сумма не учитывает. Это не «почти то же самое» — на реальных данных
переход на `total_shots` меняет `n` в фильтрах по ударам заметно (пример
в АП-4). Пороги `T_shots`/`T_sog` в решётке (РА-4) сравниваются как `>=`,
не `>` — операция не была явно названа в версии спецификации до
реализации; `>=` выбран, чтобы соответствовать всем ручным выгрузкам этого
чата («≥9/4 ударов») и АП-4. Владение (`T_poss`) сравнивается строго `>`
(РА-3 называет оператор явно).

## Бизнес-правила

- **Основная цель — РА-12 (доля ≥ 0.67/0.70), не EV.** Коэффициенты 1.7/2.4 и
  вытекающий из них EV — вторичная, информационная метрика, не критерий
  отбора. Это сознательная смена постановки задачи 13.10.2026 (см. «Цель»).
- Две целевые переменные (РА-6): «любая команда» — покрытие ≈53 % на
  отсечке 75' (отфильтрованная выборка), честный кф без маржи ≈1.88.
  «Команда с преимуществом» — покрытие ≈41-42 %, честный кф без маржи ≈2.4;
  реального рыночного кф на этот рынок нет, EV для неё не считается — только
  доля и лифт. Разница между покрытиями (~11-12 п.п. на отсечке 75') не
  маленькая по той же причине, что и раньше: часть «любой команды» — голы
  соперника в контратаку. Цели не смешиваются ни в данных, ни в отчёте, поиск
  по РА-12 ведётся по каждой отдельно.
- Дополнительное время и серия пенальти не входят в расчёт: берётся счёт
  основного времени (`COALESCE(ft90_*, goals_*)`), минуты голов — только
  `fixture_events` с `minute ≤ 90` по основному времени матча (пенальти-мисс
  не считается голом).
- Отсечка — 75' по умолчанию, параметр запуска (РА-5).
- Комбинация, где `T_poss` не достигается ни одной из команд, не считается
  «пустой» (`share=0`) — матч просто не входит в знаменатель этой
  комбинации.

## Интерпретируемость (обязательное требование владельца, 13.10.2026)

Отчёт должен быть читаем статистически, а не просто отсортированной таблицей
p-value:

- По каждой опубликованной комбинации — не только точечная доля, но и
  95 %-ДИ Уилсона, `n`, базовая доля для сравнения и лифт в процентных
  пунктах. Доля без интервала не публикуется.
- Сырой и скорректированный (BH) p-value показываются рядом, не только флаг
  «значимо/не значимо» — чтобы было видно, насколько близко к границе.
- Везде, где используются признаки замен/карточек/траектории счёта —
  обязательная короткая оговорка «ассоциация, не причина» (см. «Известные
  ограничения», п. 5): команда делает замену или получает карточку *в ответ*
  на состояние игры, а не случайно, поэтому корреляция с голом после отсечки
  не означает, что замена его вызывает.
- Везде, где используется приближение 2-го тайма (Фаза 2, РА-4а) — рядом
  показывается измеренное смещение (48.5 % / 51.5 % против ожидаемых 55.6 % /
  44.4 %, «Известные ограничения», п. 2), чтобы читатель видел направление и
  примерный масштаб завышения, а не считал цифру точной.
- Результат на train и на holdout показываются рядом для одной и той же
  комбинации, а не только итоговое «подтверждено/не подтверждено» —
  расхождение между ними само по себе информативно.
- **Для цели РА-12** — отчёт прямо называет число протестированных комбинаций
  (актуально — 14 520, не независимых друг от друга), число прошедших гейт `n≥300` и
  ДИ-порог на train, и отдельно — число подтверждённых на holdout. Если итог
  «ноль подтверждённых» — это такой же законный и полезный результат отчёта,
  как и «нашли три комбинации», и формулируется явно, а не маскируется
  понижением порога постфактум.

## Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Матч с ненулевым счётом без надёжных событий (РА-2) | исключается из всех комбинаций, считается отдельно в отчёте («N матчей исключено, нет событий») |
| Комбинация с `n = 0` | не публикуется как кандидат, попадает в отчёт с `n=0`, без EV |
| Обе команды ровно на пороге (`possession == T_poss`) | не засчитывается (сравнение строго `>`, как во всех предыдущих выгрузках) |
| Ничья по владению 50/50 | ни одна сторона не считается «с преимуществом» при любом `T_poss ≥ 50` |
| Сезон частично завершён (2026/2027) | не попадает ни в train, ни в holdout — только в блок «мониторинг» (РА-10), без участия в обучении/проверке значимости |
| Легаси-строки без `total_shots` (если такие остались в `fixture_statistics` до какой-то миграции) | исключаются на этапе РА-1 (поле обязательно непустое) |
| Ни одна комбинация не прошла гейт РА-12 ни на train, ни на holdout | не ошибка — законный результат, отчёт сообщает об этом явно (см. «Интерпретируемость») |
| Комбинация прошла train-гейт (0.67/n≥300), но не набрала `n≥150` на holdout | помечается «не проверено на holdout» (не «не подтверждено» — это разные вещи), в сводку кандидатов не входит |

## Тестовые сценарии

Основной: синтетический набор матчей с известными владением/ударами/
заменами/карточками/голами по минутам → ожидаемые `n`/`share`/ДИ/`EV` по
каждой комбинации и по обеим целевым переменным совпадают с ручным расчётом.
Граничные: пустая решётка (один порог), комбинация с `n=0`, все матчи с
одинаковым исходом (`share=0` или `1`, EV считается, ДИ и p-value —
предельный случай). Некорректный ввод: порог вне диапазона `0–100` для
владения, отрицательный кф. Надёжность: матч с ненулевым счётом без событий
(должен исключиться), матч 0:0 без событий (не должен исключиться).
Переобучение: на искусственных данных без реального эффекта после поправки
ни одна комбинация не должна проходить порог значимости чаще, чем ожидаемо по
уровню `α` (контроль ложных открытий), раздельно для train и holdout.
Разделение по сезонам: матч из 2026/2027 никогда не попадает в train/holdout
агрегаты, только в отдельный монитор-срез. Гейт РА-12: комбинация на границе
(ДИ-нижняя ровно 0.67) включается; комбинация чуть ниже (0.6699) — нет; train
пройден/holdout не набрал `n` → статус «не проверено», не «не подтверждено»;
train пройден/holdout ниже 0.60 → «не подтверждено», видно в отчёте явно.
