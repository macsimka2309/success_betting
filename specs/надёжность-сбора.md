# Надёжность сбора и архив наблюдений

Основание: анализ 01.11.2026 и поручение владельца начать предложенные доработки.
Статус: выложено на vac-ru 01.11.2026 в 21:58 МСК, миграция 019 применена.

## Контракт

1. Для статистики, таймов и составов различаются loaded, empty, partial,
   error и exhausted. Последний означает исчерпанные попытки, а не отсутствие
   поддержки источником. Покрытие по-прежнему определяется league_seasons.
2. Полнота: обе команды матча; для статистики хотя бы один непустой показатель
   каждой команды, для таймов — каждого тайма каждой команды, для составов —
   непустой startXI каждой команды. Это полнота структуры, не гарантия всех полей.
3. Пустые/частичные ответы повторяются через 24 часа, максимум четыре попытки.
   Ошибки — максимум три. Завершённые результаты и старые отметки автоматически
   не сбрасываются. Пустые события допустимы: матч может пройти без событий.
4. Каждая новая попытка читает источник, а не сохранённый пустой кэш.
5. Успешные сетевые ответы заданий collection_runs сохраняются append-only
   в api_observations: run_id, endpoint, параметры, requested_at, observed_at,
   JSON ответа. Секретные заголовки и ключи не сохраняются. Ответ из кэша новым
   наблюдением не считается. Ошибка записи архива прерывает шаг.
6. Архив включает все live-ответы, в том числе матчи без сигнала. Кэш и очистка
   временных снимков перерыва на архив не влияют. Это начало накопления истории,
   не восстановление прошлых наблюдений.
7. Live-коэффициенты: отдельный opt-in job live-odds; автоматический запуск
   включается при выкладке после согласования бюджета и объёма архива.
8. Построение upcoming запускается в daily после успешного окончания свежих
   шагов и до исторической дозагрузки. Ошибка транспорта/API или исчерпание бюджета свежего шага
   запрещает запуск признаков. Успешный пустой/частичный набор конкретного матча
   учитывается в качестве данных и не блокирует весь daily: признаки должны
   обрабатывать отсутствующие значения по своему действующему контракту. Отдельный cron 09:30 удаляется из шаблона.

## Миграция и эксплуатация

019 добавляет две таблицы; исходные данные и прежние отметки не переписываются.
Сначала миграция, затем код. Откат кода возможен без удаления таблиц; down удаляет
архив и состояния, поэтому требует отдельного решения. Архив хранится без
автоудаления: перед production оценить рост диска на пробном ограниченном сборе.
Старые ложные отметки исправляются отдельной проверенной процедурой, не миграцией.

## Проверки

Пустой ответ → ожидание → свежий повтор → loaded; четыре пустых ответа → exhausted;
часть команд/таймов → partial; успехи не дублируют строки фактов; архив сохраняет
разные ответы одинакового запроса; кэш не создаёт наблюдение; ошибки/квота не
запускают признаки; признаки выполняются до backfill. Без реальных API-запросов.
