# Спецификация: серверная сверка истории Fonbet с реестром

Статус: **реализована и включена на vac-ru 10.11.2026**.
Основание: поручения владельца ежедневно переносить ставки за предыдущий день,
считать каждую ставку за 1 единицу и выполнять сбор на сервере без включённого Mac.
Дополняет [реестр ставок](реестр-ставок.md).

## Цель и границы

История личного кабинета Fonbet автоматически сверяется с PostgreSQL `football`,
таблицей `bets`, контейнером `football-postgres` на `vac-ru` (45.150.38.30).
Сверка читает историю, добавляет недостающие ставки и уточняет подтверждённые
результаты открытых записей. Размещать ставки или изменять аккаунт запрещено.

Источник — отображённая страница `https://fon.bet/account/history/bets`
в отдельном авторизованном Chromium на сервере. Safari и локальная машина
для регулярных запусков не нужны. Приватные API Fonbet не используются.
Сессия сохраняется в серверном профиле; при её истечении нужен ручной вход владельца.

## Пользовательские сценарии

1. Владелец входит в Fonbet через окно серверного браузера, доступное по SSH-туннелю.
2. В 00:00 МСК сервер читает историю за предыдущие календарные сутки и сверяет её с реестром.
3. В 00:15 и 01:00 МСК повторяет сверку: обновляет результаты и добавляет ставки,
   которые ранее нельзя было внести без идентификатора до расчёта.
4. После ошибки или пропуска оператор повторяет запуск за конкретную дату.
   Повторный импорт не создаёт дублей.

## Правила отбора и сохранения

- ФБ-1. День отбора определяется по **времени размещения** в `Europe/Moscow`:
  от 00:00 включительно до 00:00 следующего дня исключительно.
  Начало матча и время расчёта не определяют день импорта.
- ФБ-2. Сборщик обходит виртуальную прокрутку истории до конца и раскрывает детали
  купонов нужных дат. Кроме выбранного дня запрашиваются даты размещения уже
  открытых ставок. Новые записи за другие дни не добавляются.
- ФБ-3. Сохраняются номер купона, обе команды, рынок, линия, коэффициент,
  начало матча, размещение, подтверждённый статус, итоговый счёт и время расчёта.
  `stake = 1` независимо от денежной суммы в Fonbet.
- ФБ-4. Поддерживаются одиночные ставки `TB`, `TM`, `ITB1`, `ITB2` с положительной
  линией, кратной 0,5, и коэффициентом больше 1. Экспрессы, четвертные линии,
  продажи и неизвестные рынки/форматы/статусы пропускаются с причиной.
  Это ограничение импорта; штатный расчёт реестра по-прежнему поддерживает четвертные линии.
- ФБ-5. Импорт не вычисляет исход по счёту: использует статус, подтверждённый Fonbet.
  Текущие поддерживаемые обозначения: «Выигрышный прогноз» → `won`,
  «Проигрышный прогноз» → `lost`, «Возврат» → `push`,
  «Не рассчитан» / «Не рассчитана» → `open`.
  Прибыль в единицах: `won` → `odds − 1`, `lost` → `−1`, `push` → `0`;
  у `open` результат и время расчёта пусты. Другие обозначения требуют проверки.
- ФБ-6. Уже рассчитанный результат автоматически не перезаписывается при расхождении
  с историей. Обновляется только переход из `open` в подтверждённый рассчитанный статус.
- ФБ-7. Отбор по дате размещения не меняет группировку отчётов Telegram-бота:
  там применяется московская дата `COALESCE(kickoff_at, created_at)`.

## Идентификация матча и защита от дублей

1. Основной ключ сверки — `fonbet_coupon_id`. Он уникален среди непустых значений.
2. Для старых записей без номера купона проверяются время размещения с допуском
   ±2 секунды, рынок, линия и коэффициент. Совпадение подтверждается названиями
   обеих команд: ручными полями либо строкой `live_alerts_sent` того же `fixture_id`.
   При одном подтверждённом совпадении запись получает номер купона.
   Несколько кандидатов или неподтверждённые названия приводят к пропуску,
   а не к созданию второй записи.
3. Для новой ставки `fixture_id` берётся только из `live_alerts_sent`, если названия
   обеих команд совпадают без учёта регистра, а начало матча отличается менее чем
   на 6 часов. Повторные оповещения одного матча считаются одним кандидатом.
   Несколько разных `fixture_id` — неоднозначность, ставка пропускается.
4. Если идентификатор не найден, рассчитанная ставка сохраняется с `fixture_id = NULL`
   и названиями в `manual_home_name`, `manual_away_name`.
   Открытая ставка без ID не записывается из-за ограничения схемы и отражается в пропусках.
5. Запись одного экспорта выполняется в транзакции с advisory-блокировкой и блокировкой
   `bets` в режиме `SHARE ROW EXCLUSIVE`. Уникальный индекс дополнительно защищает
   номер купона. SQL-ошибка откатывает транзакцию целиком.

## Данные и компоненты

## Отчёты, ошибки и восстановление

В `output/last-result.json` сохраняются дата, число найденных купонов,
признак записи, результаты `added` / `updated` / `existing` / `skipped`,
номера купонов и причины пропусков. Ошибки разбора перечислены отдельно в `skipped`.
`history-YYYY-MM-DD.json` содержит последний экспорт за день.
`last-success.txt` и `last-error.txt` фиксируют время успеха и последней ошибки;
файл ошибки может быть старше последнего успешного запуска.
Журнал службы доступен через `journalctl`. Отправка этих отчётов в Telegram
в текущую реализацию не входит.

| Ситуация | Поведение |
|---|---|
| Истекла сессия, история недоступна | запуск завершается ошибкой, новые записи не вносятся; владелец входит повторно |
| Не загрузились детали или не завершён обход | импорт этого запуска блокируется; предел обхода — 400 шагов и 240 секунд |
| Неподдерживаемый купон | пропуск с причиной; остальные распознанные ставки обрабатываются |
| Ставка без ID ещё открыта | пропуск; повтор после расчёта может добавить её с ручными названиями |
| Расхождение или неоднозначное совпадение | пропуск, существующая запись не перезаписывается |
| Предыдущий запуск ещё идёт | новый запуск пропускается по `flock` |
| Ошибка БД | транзакция откатывается; следующий запуск повторяет сверку |
| Сервер был выключен | systemd догоняет пропущенный запуск; несколько пропущенных дней требуют запуска по каждой дате |

Повтор за конкретный день:

```sh
bash /opt/apps/fonbet-sync-pilot/run_fonbet_sync.sh 2026-11-09
```

Ограничение: обход до конца относится к истории, которую предоставляет страница;
доступность всех требуемых дат зависит от её периода, фильтров и интерфейса.
Изменение вёрстки или форматов Fonbet может потребовать обновления сборщика.

## Безопасность

- Владелец сам вводит пароль и код в форму сайта. Не читать и не выводить `.env`,
  приватные ключи, cookies, пароли и содержимое профиля.
- Профиль и каталог отчётов закрыты правами 700, файлы отчётов — 600;
  профиль и выгрузки не попадают в Git.
- noVNC опубликован только на `127.0.0.1:6080` сервера; окно открывается через SSH-туннель.
  Порт управления Chromium 9222 доступен только внутри контейнера, наружу не опубликован.
- Браузер ограничен 1 ГБ памяти и одним CPU. Чтение истории не расходует лимит API-Football.

## Устранение ночного сбоя 12.11.2026

Владелец согласовал: сериализацию тяжёлого чтения live/history с приоритетом
live, корректный запуск и остановку Xvfb, разделение этапов восстановления,
поддержку новых статусов истории и повторную сверку четырёх купонов за 11 ноября.
Миграций, увеличения памяти и изменения API/правил сигналов нет.

Общая host-блокировка output/browser.lock удерживается только на время чтения
в браузере. Live получает её без ожидания, занятый запуск пропускается без очереди.
История ждёт максимум 90 секунд, уступает активному collect.lock и первую минуту
каждого пятиминутного слота; начатое чтение истории не прерывается. Это приоритет
при допуске, а не вытеснение. В контейнере обе команды дополнительно удерживают
/profile/fonbet-browser.lock, чтобы пережить потерю docker exec/SSH клиента.
Плановые часы таймеров не меняются. Watchdog получает обе per-job блокировки и
общую host-блокировку перед рестартом.

Supervisor владеет Xvfb, VNC, websockify и браузером; TERM/INT корректно завершают
дочерние процессы. Готовность дисплея подтверждает X11-handshake. Точные устаревшие
/tmp/.X<N>-lock и /tmp/.X11-unix/X<N> удаляются только при недоступном дисплее,
отсутствии X-сервера этого номера в /proc и безопасном владельце/типе файла.
Действующий дисплей не останавливается и не очищается. Профиль не удаляется.

Состояния watchdog: требуется рестарт → браузер запускается → браузер доступен,
ожидается статистика → сбор подтверждён. Команда рестарта и поколение контейнера
запоминаются до действия. Отложенная готовность после выполненного рестарта снимает
требование нового рестарта; ожидание реального матча не перезапускает браузер.
Экспорт до последнего рестарта не может подтвердить восстановление и не вызывает
новый рестарт по старому run_id. Прежние лимиты 15 минут/3 попытки в час сохраняются.

«Выигрыш» и «Проигрыш» — точные дополнительные обозначения won/lost наряду со
старыми подписями. Неподдерживаемый статус по-прежнему пропускается. Отчёт импорта
содержит complete/partial и количество пропусков (разбор и сверка); неполный запуск
не обновляет last-success и вызывает предупреждение watchdog. Отчёт сохраняется
перед ненулевым кодом завершения. Дедупликация, транзакция, 1 единица, правила
NULL fixture_id и запрет перезаписи рассчитанного результата сохраняются.

Приёмка: конкурирующие live/history, приоритет и таймаут, второй независимый
container-lock, stale X lock с повторно использованным PID, отказ менять живой
дисплей, TERM и два рестарта, отложенная готовность CDP, отсутствие матчей,
новый OOM после восстановления, старый экспорт, неизвестный статус и все четыре
купона с идемпотентным повтором. Полуночная нагрузочная приёмка остаётся отдельной.


## Переключение центров и память, 12.11.2026 вечером

По согласованному плану причины ошибок различаются безопасными кодами:
selector_ambiguous, element_detached, navigation_interrupted и прежние коды.
В диагностике только число центров и названия изменившихся полей, без значений,
URL, DOM, сообщений исключений или аккаунта. Вложенные ancestor-контейнеры
одного центра исключаются; два настоящих центра не выбираются через first().
Invalid_context допускает один повтор на новой странице с повторным поиском ID
и минуты, без расширения бюджета 600 секунд. Минута >75 по-прежнему исключается.
В summary.memory сохраняются этапы до/после обнаружения, событий и закрытия,
anon/inactive_file/working_set; кеш не объявляется утечкой.
После успешного полного экспорта истории её страница закрывается после создания
новой about:blank страницы в том же контексте; следующий экспорт поддерживает нейтральную стартовую страницу.
Сессия остаётся в том же persistent context, при ошибке страница входа сохраняется.
Миграции, пороги сигналов, расписания, лимиты и профиль не меняются.
Приёмка: вложенные/два независимых центра, безопасная диагностика, ограниченный
повтор и выход из окна, два успешных экспорта подряд с парковкой страницы,
реальная проверка переключения и отсутствие новых OOM.

## Одиночные фрибеты — уточнение владельца 14.11.2026

Реальная подпись купона Fonbet: «Одинар\nФрибет», детали содержат один исход.
Фрибет — источник средств, а не экспресс. При ровно одном исходе поддерживаются
точные токены «Одинар» и «Одинар Фрибет» после нормализации пробелов/переносов.
Неизвестные метки, настоящий экспресс и несколько исходов остаются пропусками.

Миграция 029 добавляет bets.is_freebet BOOLEAN NOT NULL DEFAULT false;
обычные ставки и прежние ручные записи совместимы. При импорте фрибета поле true.
Маркер не выводится из суммы ставки/выплаты, результата или коэффициента.
Повторная сверка подтверждённого купона может уточнить маркер false→true,
но не меняет уже рассчитанный статус/прибыль. True→false считается расхождением.

По действующему требованию владельца каждая ставка остаётся 1 условной единицей:
прибыль в реестре won=odds−1, lost=−1, push=0. Это нормализованная оценка ставок,
не денежный баланс бонусов Fonbet; финансовая модель и отчёты не меняются.
В отчёт импорта добавляется число распознанных freebet_count.
