# Общая выборка live-срезов API-Football и Fonbet

Поручение владельца 10.11.2026. Основной источник — API-Football, дополнительные
матчи поступают из Fonbet. Окно обоих источников — 65–75, одна последняя
непустая строка на матч каждого источника, с сохранением фактических минут.

## Объединение

Исходные таблицы 023 и 025 сохраняют срезы и собственные идентификаторы.
Общая SQL-выборка live_match_statistics_75_combined возвращает одну строку
на подтверждённый матч API-Football. При наличии API-среза выбирается он,
включая частичные ответы. Если API-среза нет, используется подтверждённый
срез Fonbet. Его порядок команд разворачивается к API при необходимости.
Показатели разных источников не склеиваются. Ссылка на дополнительный снимок
Fonbet остаётся доступна для сравнения. Несколько событий Fonbet, связанных
с одним fixture_id, дают один последний срез по минуте/времени/ID события.

Несопоставленный матч сохраняется с canonical_match_id=fonbet:<event_id>,
fixture_id=NULL и исходными названиями. Подтверждённый имеет ключ api:<fixture_id>.
После появления подтверждённой связи выборка автоматически схлопывает строки.
ID Fonbet никогда не записывается в fixtures как ID API-Football.

## Правила сопоставления первой версии

Нормализация имён сохраняет буквенные/цифровые токены, возраст, женскую команду,
резервы. Убираются только различия регистра, Unicode-представления и пунктуации.
Разные языки и сокращения требуют проверенных алиасов команды и турнира.
Нечёткое сходство само по себе не подтверждает пару.

Подтверждаются обе команды, турнир, порядок команд (включая обратный) и время.
При известном kickoff Fonbet допускается разница начала до 10 минут. Если kickoff
отсутствует, нужны близкие live-срезы API и Fonbet — не более 120 секунд между
наблюдениями, не более 3 минут по часам и одинаковый известный счёт после
выравнивания команд. Должен остаться ровно один кандидат. Эти консервативные
допуски выбраны при реализации и доступны владельцу для проверки.

Несколько подходящих кандидатов дают ambiguous, отсутствие — unmatched.
Сохраняются кандидаты и причина, решение и версия алгоритма попадают в аудит.
Подтверждённые связи сохраняются между обновлениями среза. Изменение проверенной
связи выполняется отдельной явной операцией, а не из браузерного JSON.

## Интеграция и проверки

Сопоставление выполняется после сохранения очередного Fonbet-экспорта и повторно
проверяет накопленные несвязанные события, когда API уже загрузил свой матч.
Используется блокировка Fonbet-сбора. Решение применяется лишь к той версии
среза, по которой рассчитано, и не перезаписывает подтверждённую параллельно связь.
Браузерный ввод не может задавать mapping-поля. Сохраняются ограничения чата
«Ставки+бот» на FC, футзал, микрофутзал и 2X40.

Критерии — основной API при обоих источниках, Fonbet при отсутствии API-среза,
сохранение Fonbet-only, обратный порядок, позднее появление API, дубли событий,
неоднозначные имена, U20/женщины/резерв, расхождение времени и счёта, повтор и
конкурентное сопоставление, сохранение NULL и нулей. Старые API-строки не меняются.

Миграция 026 добавляет поля сопоставления к 025, проверенные алиасы, аудит
и общую view. Миграция 025 должна быть применена раньше. Откат приложения
сохраняет срезы, down 026 удаляет только добавленный слой объединения.


## Production-приёмка 10.11.2026

в `/backups/football_schema_before_025_026_20261110.sql` контейнера PostgreSQL.
Первый настоящий срез Fonbet: 69791872, 75-я минута, 1:1, удары в створ 2:0.
После отдельной проверки страны, турнира, обеих команд, даты и kickoff API
он вручную сопоставлен с fixture_id=1646997 (reviewed_live_identity_v1);
синхронного API-снимка у этой пары не было. Автоматический алгоритм

## Использование для оповещений (спецификация 10.11.2026)

[Общий диспетчер уведомлений](оповещения-по-общим-live-данным.md) использует
срезы и подтверждённые связи этого слоя. Для оперативной отправки отдельно
проверяются свежесть и определимость триггера: свежий пригодный API приоритетен,
при его отсутствии/устаревании/недостаточных полях допускается Fonbet.
Аналитическая view сохраняет прежний приоритет API при наличии среза;
она не меняется и сама по себе не является очередью или текущим live-статусом.
Позднее сопоставление требует сохранения алиасов идентичности оповещений,
иначе смена canonical_match_id может породить повторную карточку.


## Уточнение 12.11.2026: голы входят в нормализованные удары

По поручению владельца для Fonbet исходные удары в створ второго тайма
дополняются голами именно второго тайма к моменту снимка. Сырые значения
не меняются; аналитика и уведомления используют нормализованный результат.
Неизвестный счёт к перерыву не считается нулевым. Контракт и проверки:
[нормализация-ударов-fonbet.md](нормализация-ударов-fonbet.md).

## Ограничение поиска кандидатов по датам (14.11.2026)

При росте числа неподтверждённых снимков запрос сопоставления превысил 30 секунд
после успешного сохранения live-данных. Не менять критерии идентичности/времени
и не увеличивать таймаут. Предварительно ограничить fixtures.match_date диапазоном
всех допустимых kickoff: observed_at−4ч…observed_at и kickoff_at±10мин,
с запасом по одному календарному дню с обеих сторон UTC. Дата матча хранится
по kickoff; используется существующий idx_fixtures_match_date. Исходный EXISTS
с точными временными окнами остаётся обязательным. Известный kickoff может быть
в другой дате, чем observed_at: оба диапазона должны входить в границы.

Список неподтверждённых снимков вычисляется один раз (MATERIALIZED CTE), архив
не ограничивается последними сутками, старые пары не теряются. Пустой список
не выбирает кандидатов. Подтверждённые связи не меняются. При SQL-таймауте журнал
должен сообщать безопасный код matching_query_timeout без SQL/параметров.
Проверка: прежние тесты сопоставления, позднее появление API, другой день kickoff,
граница суток, пустая очередь; измерение READ ONLY на production и успешный
штатный цикл с сохранением/сопоставлением. Схема и индексы не меняются.

Приёмка оптимизации: READ ONLY на production 1,796 сек вместо timeout 30 сек;
71 проверка успешна. После выкладки полный цикл 14.11 10:25 МСК сохранил
5 новых снимков и завершил сопоставление 487 неподтверждённых строк без ошибки.
