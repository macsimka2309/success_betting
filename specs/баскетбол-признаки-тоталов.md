# Спецификация: каталог признаков для тоталов в баскетболе

Статус: черновик, на согласовании владельцем. Чат «Обработка данных (BB)».
Связанные документы: `specs/баскетбол-сбор-данных.md` (источник данных), `docs/03-модель-данных.md`, миграция `016_basketball_schema.sql`.

## 1. Цель и границы

Собрать **каталог признаков**, которые можно получить для прогноза тотала (прематч и лайв), и для каждого указать: есть ли он в БД, как его получить, чего не хватает и как это добыть.

Что **не** входит и не фиксируется этой спецификацией: формула прогноза, выбор модели, веса признаков, способ смешивания прематча и лайва, окна и коэффициенты затухания. Всё это решается на этапе моделирования и проверяется на данных. Ниже даны только определения признаков и источники.

Из найденных материалов (CMU capstone, диссертация Iowa State, блоги LSports и ставочные гайды) взят только перечень факторов: темп, эффективность, отдых, состав, овертайм, фолы. Размеры эффектов из этих источников не используются.

## 2. Общие правила генерации

- Признак команды в матче строится **только по играм до `tip_off` этого матча** (запрет утечки).
- Для каждого признака разрешены варианты агрегации: среднее за N последних игр, взвешенное, сезонное, раздельно дом/выезд; конкретные выбираются при моделировании.
- Пустое значение остаётся NULL, плюс индикатор «нет данных»; нули вместо пропусков не ставим.
- Все признаки пишутся в отдельные витрины через миграции; исходные таблицы схемы `basketball` не меняются.
- Идентификаторы: матч `game_id`, команда `team_id`, игрок `player_id`; лига и сезон из `games`.

## 3. Каталог признаков

Обозначения источников: **G** = `basketball.games`, **T** = `team_game_stats`, **P** = `player_game_stats`, **O** = `odds_snapshots` + `odds_values`, **L** = `leagues`/`league_seasons`.
Состояние: ✅ есть в БД; 🔧 вычисляется из имеющегося; ➕ нужно добывать.

### 3.1 Прямые показатели матча (по завершённым играм, основа скользящих признаков)

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Очки команды: итого, по четвертям, овертайм | G | ✅ | поля `*_q1..q4`, `*_ot`, `*_total` |
| Сумма очков матча, по четвертям, по половинам | G | 🔧 | сложение полей G |
| Был ли овертайм | G | 🔧 | `home_ot` или `away_ot` не NULL и >0 |
| Попытки и попадания: с игры, трёхочковые, штрафные | T | ✅ | поля `fg_*`, `three_*`, `ft_*` |
| Подборы (всего, в нападении, в защите), передачи, перехваты, блоки, потери, фолы | T | ✅ | `reb_*`, `assists`, `steals`, `blocks`, `turnovers`, `personal_fouls`; у NBA с 01.2026 нет подборов в нападении/защите и фолов (NULL) |
| Минуты, очки, броски, подборы, передачи, стартовый состав по игроку | P | ✅ | поля P |

### 3.2 Темп и эффективность (производные)

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Число владений команды и матча | T | 🔧 | оценка из бросков, штрафных, подборов в нападении и потерь; точный вариант оценки выбирается позже. Для NBA с 2026 без подборов в нападении нужен другой вариант (см. §5) |
| Темп (владения на 48 минут), темп в равных играх | T, G | 🔧 | делением на длительность; «равные» игры по разнице итоговых очков |
| Очки на владение: атака и защита | T, G | 🔧 | очки / владения; для защиты — по очкам соперника |
| eFG%, TS%, доля трёхочковых, процент штрафных | T | 🔧 | из попыток/попаданий |
| Доли потерь, подборов в нападении, штрафных на бросок | T | 🔧 | где нет подборов в нападении — NULL и индикатор |
| Рейтинг силы атаки/защиты с поправкой на соперников | T, G | 🔧 | итерационный расчёт по всем играм лиги до даты матча |
| Профиль четвертей команды и лиги | G | 🔧 | средние очки по четвертям, доля очков во второй половине |
| Доля игр с овертаймом и больших разрывов | G | 🔧 | частоты по завершённым играм |

### 3.3 Состав и минуты

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Доля минут/очков игроков, которых нет в протоколе | P | 🔧 | топ-N по минутам за последние игры команды; отсутствие в протоколе матча |
| Устойчивость ротации (число игроков с заметными минутами) | P | 🔧 | счёт игроков выше порога минут |
| Заявленный состав до матча, травмы | — | ➕ | в API-Basketball нет; вариант: внешний источник (§5) |
| Сила состава (вклад игроков) | P | 🔧 | по накопленной статистике игроков |

### 3.4 Календарь

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Дни отдыха обеих команд, разница | G | 🔧 | разница дат предыдущей игры любой лиги |
| Back-to-back, серия игр за короткий срок | G | 🔧 | счёт игр в окне дней |
| Серия выездных игр | G | 🔧 | по `home_team_id`/`away_team_id` |
| Перелёты и часовые пояса | G, venue | ➕ | нужны координаты арен/городов; справочник добывать отдельно |
| Стадия сезона и плей-офф | G | ✅ | `stage`, `week`, номер игры в сезоне считается |

### 3.5 Контекст

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Лига, сезон, средний тотал лиги и сезона | G, L | 🔧 | агрегаты по завершённым играм |

### 3.6 Рынок

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Линии и коэффициенты Over/Under: матч, четверти, половины, овертайм | O | ✅ с 21.10.2026 | два снимка в сутки, основная линия и по две ближайшие с каждой стороны |
| Движение линии, разница Pinnacle и 1xBet | O | 🔧 | сравнение снимков |

### 3.7 Лайв (по ходу матча)

| Признак | Источник | Состояние | Как получить |
|---|---|---|---|
| Счёт по четвертям в процессе | API-Basketball, идущие матчи | ➕ | не собирается; нужен опрос идущих матчей |
| Текущее время игры, владения, броски, фолы, штрафные | API-Basketball | ➕ | неизвестно, что отдаёт API по идущим матчам; сначала проверка |
| Живая линия тотала и коэффициенты | API-Basketball | ➕ | живые коэффициенты по тарифу; проверить доступность |
| Оставшееся время, разница в счёте | счёт + время | 🔧 | при наличии лайв-данных |
| Прематч-признаки матча как исходное состояние | §3.1–3.6 | 🔧 | та же витрина, зафиксированная на момент начала матча |

## 4. Порядок работ (план, формулы не фиксируются)

1. Проверить на сервере (чат «Выгрузка баскетбол»), что API отдаёт по идущим матчам и по живым коэффициентам; результат занести в §3.7.
2. Построить витрину прематч-признаков из §3.1–3.5 (все ✅ и 🔧), с индикаторами пропусков.
3. Добавить рыночные признаки §3.6 по мере накопления снимков.
4. Решения по ➕ принимает владелец (§5).
5. Моделирование и выбор формул — отдельным этапом после готовой витрины.

## 5. Недостающее и как это добыть

| Пробел | Варианты | Решение |
|---|---|---|
| Владения у NBA с 01.2026 (нет подборов в нападении) | оценка по другой формуле; импутация по средним команды; исключение периода | решает владелец |
| Травмы и заявленные составы | внешний источник; восстановление по протоколам прошлых матчей (уже в §3.3) | открыт |
| Судьи | внешний источник (потребует отдельной спецификации сбора) | открыт |
| Координаты арен и часовые пояса | справочник вручную или из открытых данных | открыт |
| Линии прошлых лет | сторонний архив коэффициентов; иначе обучение без линии | открыт |
| Лайв | сбор идущих матчей с собственным расписанием опроса | зависит от §4 п.1 |

## 6. Критерии приёмки и тесты

- Тест на утечку: признак матча не меняется, если изменить данные матчей с датой не раньше `tip_off`.
- Сверка производных признаков (владения, рейтинги) с ручным расчётом на 3–5 матчах.
- Пропуски дают NULL и индикатор, не нули.
- Воспроизводимость: повторный расчёт даёт идентичный результат.
- Покрытие: отчёт доли заполненности каждого признака по лигам и сезонам.

## 7. Безопасность и границы

Только чтение схемы `basketball`; новые витрины создаются миграциями без разрушительных операций. Сбор данных остаётся зоной чата «Выгрузка баскетбол», запросы на новые источники согласуются с ним.
