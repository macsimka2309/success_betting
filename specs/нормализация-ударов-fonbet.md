# Fonbet: добавление голов второго тайма к ударам в створ

Уточнение владельца 12.11.2026: показатель Fonbet «Удары в створ» не включает
голы. Для сопоставления с shots_on_goal API-Football голы второго тайма
прибавляются отдельно каждой команде. Это уточняет спецификации сбора,
объединения и общих уведомлений; правила приоритета API и дедупликации не меняются.

## Формула и происхождение

normalized_shots_2h_home = shots_on_target_2h_home + goals_home - ht_home;
для гостей аналогично. goals_* — счёт на момент исходного среза (65–75),
ht_* — счёт к перерыву из того же спортивного табло Fonbet. Итоговый счёт матча,
события после среза и голы первого тайма в прибавку не входят. API не корректируется.

Исходные shots_on_target_2h_* и архив наблюдений сохраняют значения сайта.
Добавочная миграция 028 вводит nullable ht_home/ht_away и отдельный VIEW
fonbet_live_statistics_75_normalized с goals_2h_* и shots_including_goals_2h_*.
Общая аналитическая выборка и dispatcher используют нормализованные показатели;
ориентация команд меняется после расчёта. Ни браузер, ни повторный импорт
не прибавляют голы к исходным полям, повторное чтение не удваивает результат.

## Извлечение и ошибки

В табло матч-центра найти единственный блок с заголовками периодов «1», «2»;
колонку «1» читать в обеих строках команд. Не использовать карточки, угловые
или положение колонки без проверки заголовков. Убедиться, что сумма счёта
двух таймов равна общему счёту каждой команды. Два чтения команд, счёта и
статистики должны совпасть, иначе invalid_context и следующий штатный опрос.
Неизвестная/неоднозначная разбивка даёт ht_*=NULL, исходные удары сохраняются.

Если текущий счёт/счёт к перерыву неизвестен или противоречив, нормализованный
показатель соответствующей команды NULL. Прочерк ударов не превращается
в число голов. Это исключает неподтверждённый показатель из вычисления
триггера; известная другая сторона может сработать по прежнему правилу ≥5.
Старые срезы без разбивки остаются сырыми, без догадок или подстановки
более поздней статистики. Массовая рассылка исторических исправлений запрещена.

## План, совместимость и проверка

1. Добавить чтение проверенных колонок таймов и сохранение ht_* в JSON/БД.
2. Создать нормализованную выборку, подключить аналитику и dispatcher.
3. Проверить случаи: счёт 3:1, перерыв 1:1, сырые удары 4:2 → 6:2;
   нули, несколько голов, неизвестный/неверный счёт, частичные удары,
   обратный порядок команд, повторный импорт и неизменность API.
4. Применить 028 транзакционно с коротким lock_timeout; перед этим сохранить
   прежние файлы и схему. Миграция не переписывает исторические наблюдения.
   NULL по умолчанию позволяет старому сборщику писать во время перехода.
5. Проверить реальное спортивное табло, штатный сбор и SQL в production.

Откат: вернуть прежний запрос dispatcher и общую view, код сборщика;
исходные поля/наблюдения сохранены. Down удаляет только новые поля/представление;
обычный откат кода их сохраняет. Не запускать реальные тестовые рассылки.
