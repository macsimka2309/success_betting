# Серверная сверка Fonbet

Отдельный браузер и сборщик находятся на vac-ru в `/opt/apps/fonbet-sync-pilot`.
Основной проект и его .env не используются. Playwright читает только отображённую
историю; ставки не размещает и аккаунт не изменяет. Авторизация выполняется владельцем
в окне Chromium. Профиль хранится только на сервере в каталоге с правами 700.

`export.cjs` подключается к Chromium на порту 9222 внутри контейнера, обходит
виртуальную прокрутку до конца и раскрывает купоны нужных дат. Ошибка авторизации,
загрузки деталей или незавершённый обход блокируют импорт. `import_history.py`
проверяет формат, выбирает новые ставки по дате **размещения** в Europe/Moscow
и обновляет подтверждённые результаты ранее открытых ставок.

Запись идёт в одной транзакции с блокировкой таблицы bets и уникальным номером
купона `fonbet_coupon_id` (миграция 024). Старые записи сопоставляются по времени
±2 секунды, рынку, линии, коэффициенту и подтверждённым названиям команд.
Неоднозначности пропускаются. fixture_id берётся только из однозначного совпадения
названий и времени в live_alerts_sent. Рассчитанные ставки без ID сохраняются с
ручными названиями; открытые без ID пропускаются. Каждая новая ставка — 1 единица.
Ночная сверка принимает одиночные ставки и одиночные фрибеты на общий тотал
больше (ТБ) с целыми и половинными линиями. ТМ, индивидуальные тоталы, экспрессы
и остальные рынки пропускаются до импорта. Ошибки разбора распознанного ТБ
требуют ручной проверки. Дополнительные даты для сверки берутся из открытых ТБ.

Сервис `football-fonbet-sync.service`, таймер `football-fonbet-sync.timer`:
00:00, 00:15 и 01:00 Europe/Moscow. Повторы обновляют результаты и подхватывают
рассчитанные ставки без ID. При недоступном сервере systemd выполняет пропущенный
запуск после старта; многодневный простой требует ручного запуска по каждой дате.

Проверки (не выводят профиль и секреты):

```sh
systemctl list-timers football-fonbet-sync.timer
systemctl status football-fonbet-sync.service
journalctl -u football-fonbet-sync.service -n 30
cat /opt/apps/fonbet-sync-pilot/output/last-result.json
bash /opt/apps/fonbet-sync-pilot/run_fonbet_sync.sh 2026-11-09
```

Отчёты содержат финансовые сведения: каталог output закрыт правами 700,
файлы 600. `last-success.txt` фиксирует успешный проход; `last-error.txt` — последнюю
ошибку, которая может быть старше последнего успешного прохода. Пропуски находятся
в `last-result.json`. Предупреждения о неполном импорте и сбоях отправляет watchdog.

При истечении сессии нужен ручной повторный вход. Браузер доступен только через
локальный порт сервера 6080 и SSH-туннель:

```sh
ssh -N -L 127.0.0.1:6087:127.0.0.1:6080 vac-ru
```

Окно: `http://127.0.0.1:6087/vnc.html?autoconnect=true&resize=scale`.
Порт 9222 наружу не публикуется. Профиль, .env, cookies и пароли нельзя копировать
в Git или выводить в журналы. Образ собирается из официального Playwright;
`package.json`, browser/start-browser и node_modules монтируются из серверного
каталога, профиль — отдельно в `/profile`.

Проверка разбора: `python3 -m unittest discover -s tools/fonbet_sync -p 'test_*.py'`.


## Исправление ночной конкуренции, 12.11.2026

`browser_lock.py` сериализует тяжёлые чтения live/history через output/browser.lock;
обе команды держат также /profile/fonbet-browser.lock внутри контейнера.
Live не ждёт, история ждёт до 90 секунд и уступает активному live и первую минуту
каждого пятиминутного слота. Уже начатая история не прерывается. Захват/освобождение
и длительность блокировки видны в journal как browser_gate acquired/released.
Перезапуск watchdog получает оба per-job lock и browser.lock.

`start-browser.sh` запускает Python-supervisor, который проверяет X11 handshake,
убирает только подтверждённые stale артефакты конкретного дисплея и корректно
останавливает дочерние процессы. Xvfb работает с -noreset; наличие сокета само
по себе не означает готовность. Закрытый /tmp/fonbet-browser-ready отмечает
завершение начальной навигации; probe и wrappers не начинают чтение раньше.
Профиль и порты не меняются. Python3 уже есть в используемом образе Playwright.

Отчёт импорта включает только отобранные купоны. Полный обход без подходящих
купонов даёт `status=complete` и нулевые счётчики. Ошибка обработки распознанного
ТБ даёт `status=partial` и код 2. Обёртка атомарно сохраняет отчёт, а watchdog
предупреждает о неполном импорте. Неполный обход истории завершает запуск
с ошибкой до импорта. Подписи «Выигрыш» и «Проигрыш» поддерживаются наряду со
старыми. При повторной сверке записи сопоставляются с прежними купонами.

При выкладке helper-файлы устанавливаются первыми, затем согласованные wrappers,
browser.cjs, browser_probe.cjs и watchdog. Под блокировками выполняется один
контролируемый рестарт для переключения supervisor. Только после готовности
освобождаются блокировки. Откат возвращает согласованный комплект файлов;
профиль, историю, данные и лимит памяти не удалять/не менять.


## Одиночные фрибеты (14.11.2026)

Подпись «Одинар Фрибет» с переносами/пробелами и одним исходом распознаётся
как одиночная ставка. Миграция 029 вводит bets.is_freebet; её нужно применить
перед новым import_history.py. В отчёте freebet_count, правила partial сохраняются.
Stake/profit остаются нормализованными единицами, не денежной выплатой бонуса.
Настоящие экспрессы и неизвестные метки не считаются поддерживаемыми одинорами.


## Лимит памяти браузера — 16.11.2026

По поручению владельца лимит fonbet-browser-pilot увеличен с 1,5 до 2 GiB
(2147483648 байт) через docker update --memory=2g --memory-swap=2g.
Дополнительный swap не включался. Изменение применено без перезапуска:
поколение 214577558 и время старта 16.11 08:27:04 МСК сохранились.
Cgroup подтверждает новый предел; browser_probe возвращает browser_ok.
При обычном рестарте контейнера Docker сохраняет этот лимит; при его
пересоздании нужно явно указывать те же параметры 2g. БД, профиль, расписание
и правила сигналов не менялись. Для возврата прежнего лимита: 1536m для обоих
параметров, предварительно проверив, что текущее потребление ниже него.
