# Design

## Context

Диспетчер сохраняет текущий снимок при отправке и передаёт его в контекст первого сигнала. API-Football коллекция сохраняет сезон в live-снимке. Таблица матчей уже хранит итог FT и отдельно счёт основного времени для AET/PEN.

## Goals / Non-Goals

**Цели.** Показать результативность лиги в первом сигнале и напоминании. Сохранить допуск по фактическим данным второго тайма и действующему триггеру.

**Вне объёма.** Изменение фактических условий ставок, правил повтора, расписания исторического сбора и учёта голов.

## Decisions

- Считать среднее по завершённым матчам того же `league_id` и сезона, доступным в PostgreSQL перед отправкой. Для FT использовать итог, для AET/PEN использовать только `ft90_home` и `ft90_away`. Пропускать неполные и отрицательные счета, отменённые и технические результаты. Показывать две десятичные цифры и количество матчей. Обновления отражаются после штатной загрузки базы.
- Использовать подтверждённый матч API-Football либо пару идентификатора лиги и сезона из его live-снимка. Для Fonbet без прямой связи допускается явно подтверждённый алиас турнира и единственный сезон по дате матча. Несовместимые идентификаторы и неоднозначные сезоны дают «нет данных». Сопоставление по похожему названию в отправщике не применяется.
- Добавлять рассчитанное значение при первом вызове Telegram. Сохранять его вместе с контекстом отправки для напоминания. Для ранее открытого напоминания без сохранённого показателя использовать идентичность из исходного контекста, если она достаточна. Ветви единого и прямого отправщиков используют один расчёт и формат.
- Основания допуска и текст сообщения разделены. Среднее на базе одного матча допустимо как справочная величина, поскольку рядом виден размер выборки. При отсутствии завершённых матчей текст выводит «нет данных». Решение о ставке остаётся за получателем.

## Risks / Trade-offs

- Результат отражает покрытие нашей базы, которое может различаться по лигам. Количество учтённых матчей указывается в сообщении.
- Метрика для Fonbet-only зависит от подтверждённых алиасов и дат сезона. Неоднозначность сохраняет отправку со статусом «нет данных».
