# Проверка исправлений пятого раунда

Все восемь предыдущих воспроизведений прошли. Три дополнительных сценария выявили способ отправить повтор по неоднозначному опросу и два нарушения идентичности голов. [Воспроизведения](repro_cases.py)

1. **P1. Снимок 75-й минуты позволяет отправить повтор по неоднозначному ответу API-Football.** Штатный сборщик обновляет список и получает один матч дважды, с отметками 74 и 75. Он берёт последнюю строку и сохраняет положительную статистику в снимке 75. Чтение архива отклоняет этот контекст. Затем диспетчер добавляет тот же снимок из проекции по совпавшему ID опроса и отправляет повтор. Снимок для аналитики должен подтверждать повтор только после проверки соответствия статистики и контекста. [Точка обхода в диспетчере](../../src/jobs/signal_reminders.py#L88) · [Проверка архива](../../src/jobs/signal_reminder_history.py#L94)
2. **P1. Пенальти на той же отметке получает ID ранее известного гола с игры.** В live виден один гол с игры на 90+2 со счётом 1:0. Финальный протокол добавляет перед ним пенальти на 90+2, прежний гол с игры становится 2:0. Специальная обработка пропускает группу с одной прежней записью. Совпавший счёт 1:0 передаёт ID пенальти, а гол с игры получает новый ID. Однозначное совпадение по типу должно сохранять прежний ID и при расширении группы. [Условие пропуска группы](../../src/jobs/signal_goal_store.py#L79)
3. **P2. Уточнение минуты оставляет три активные записи при подтверждённых двух голах.** В live два гола с игры на 90+2. Финальный протокол уточняет минуту первого до 88-й и сохраняет счёт 2:0. Сопоставление на 90+2 остаётся спорным и резервирует обе прежние записи. Для строки на 88-й создаётся новый ID, а старые строки остаются активными. Пока соответствие не разрешено, возможная коррекция минуты должна оставаться в той же сверке. [Резервирование спорных ID](../../src/jobs/signal_goal_store.py#L112) · [Добавление активной записи](../../src/jobs/signal_goal_store.py#L257)
