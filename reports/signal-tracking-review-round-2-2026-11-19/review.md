# Повторная проверка напоминаний и учёта голов

Проверка от 19.11.2026. Пять дополнительных сценариев воспроизвели дефекты. Проверялись локальный код, одноразовая PostgreSQL и подставные ответы источников. Пять сценариев сохранены в [repro_cases.py](repro_cases.py).

| Приоритет | Сценарий | Получено | Ожидалось |
|---|---|---|---|
| P1 | Полный ответ убрал гол, затем неполный снова содержит его | Отменённый гол снова активен и учтён | Гол остаётся отменённым до достоверного подтверждения |
| P1 | Частичный ответ повторяет известный автогол, но команда, которой он засчитан, неизвестна | Два подтверждённых гола после сигнала | Один подтверждённый гол. Неоднозначное наблюдение сохраняется отдельно |
| P1 | Для одного ID завершённый результат показывает 0:1, а подставленный устаревший «Ход матча» показывает 7:0 | Список принят как полный со счётом 7:0 | Статус окончания сохраняется. Список голов помечен неполным до сверки |
| P1 | API отдаёт пустой список для известного ID, а Fonbet может подтвердить завершение | Fonbet не вызывается | Попытка получения результата из Fonbet выполняется |
| P2 | Квота API исчерпана, в очереди есть матч только из Fonbet | Запрос Fonbet пропущен | Лимит API ограничивает запросы API, а доступный Fonbet проверяется |

## Изменения, которые закроют сценарии

- `src/jobs/signal_goal_store.py:45`. Отсутствие `credited_side` не доказывает различие событий. При совпадающих данных источника сохранить прежнюю идентичность или записать неоднозначность в `live_signal_goal_pending`. Учитывать `source_team_id` как отдельный признак от команды, которой засчитан автогол.
- `src/jobs/signal_goal_store.py:80`. При сопоставлении неполного ответа с неактивным голом сохранить состояние деактивации и записать новое наблюдение в историю. Повторная активация требует достоверного подтверждения.
- `src/jobs/signal_goals.py:121`. Разделить подтверждение окончания и подтверждение полноты. Сверять события с независимым счётом основного времени, если он достоверен. Общий финальный счёт после дополнительного времени и серии пенальти для этой сверки не подходит. Для воспроизведения использована реальная разметка результата с подставленным противоречащим таймлайном. Это проверка решения адаптера в конфликтной ситуации, доступность такой комбинации в live не проверялась.
- `src/jobs/signal_results.py:53`. Ранний выход без Fonbet допустим при явном статусе продолжающегося матча. Пустой API-ответ означает отсутствие записи о матче и должен позволять fallback.
- `src/jobs/signal_results.py:85`. Переносить из-за квоты отдельные этапы, которые требуют запроса API. Fonbet-only матчи и уже подготовленные этапы Fonbet продолжают обрабатываться в пределах своего бюджета.
