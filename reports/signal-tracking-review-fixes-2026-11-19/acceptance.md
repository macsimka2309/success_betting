## Исправления

1. Готовность reminder проверяется до LIMIT, terminal отменяется отдельно, используется общий deadline initial/reminder 85 секунд с резервом 30 секунд до каждого Telegram-запроса. При нехватке времени sending/uncertain не создаются. Тест «30 waiting + готовый 31-й» теперь проходит.
2. Goal ID не равен хешу вычисленного счёта. Matching сохраняет известные поля частичного ответа, использует геометрию события до mutable cumulative score, не отдаёт ID позднему вставленному голу вместо неизменившегося последующего. Provider IDs используются при наличии; внутренние UUID стабильны между версиями. Неоднозначность хранится отдельно. Миграция 033 — pending и история версий. В аналитике не возникают лишние подтверждённые события.
3. На настоящей странице результатов проверены selected «Завершенные» и строка с event ID. Обезличенный completed-result.html подтверждает формат. Протокол REG_END/evidence запускает первичную загрузку Fonbet-only даже без discovery. Итоговая таблица сама по себе не становится списком голов или regulation score. Свободный текст «Матч завершён» без identity и выбранного фильтра намеренно не подтверждает конец; прежний синтетический review-тест заменён более строгим реальным fixture в поддерживаемом suite. Доступность полного «Хода матча» после завершения не гарантируется и остаётся явной неполнотой при отсутствии.
4. Timeline.attempted/outcome и deferred_internal разделяют внешнюю попытку и отсутствие I/O. Budget/lock/memory defer не расходует счётчики. Миграция 034 хранит pending API observation, last_poll_at и deferred_reason; этап продолжается без повторного API HTTP. SQL-диагностика показывает остаток проверок, фактическую попытку и перенос отдельно. Все семь фактических проверок сохраняются после простоя.
