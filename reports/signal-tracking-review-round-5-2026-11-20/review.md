# Проверка идентичности голов и восстановления архива API

Все шесть воспроизведений третьего и четвёртого раундов прошли. Два дополнительных сценария выявили перестановку ID голов при пересчёте счёта и лишнее напоминание при восстановлении связи со старым контекстом. [Воспроизведения](repro_cases.py)

1. **P1. Добавление раннего гола меняет местами ID двух голов на 90+2.** В live сначала видны пенальти и гол с игры на 90+2 со счётом 1:0 и 2:0. Подтверждённый итог добавляет пропущенный гол на 88-й минуте. Счёт после пенальти меняется на 2:0, после гола с игры — на 3:0. Сопоставление резервирует старый ID гола с игры для пенальти из-за совпавшего счёта 2:0. В результате два существующих ID меняются местами при сохранении типа и порядка событий в исходном таймлайне. Ожидается, что новый ID получит только гол на 88-й. [Ключ и резервирование пары](../../src/jobs/signal_goal_store.py#L37)
2. **P2. Восстановление архива API подставляет более ранний контекст, если обновлённый неоднозначен.** В одном штатном запуске есть валидный ответ на 72-й минуте и более поздний обновлённый ответ, где этот матч указан дважды. Сборщик строит словарь по ID матча и использует последнюю строку обновлённого ответа. При отсутствии явной привязки восстановление отбрасывает ответ с дублем, принимает контекст на 72-й и разрешает повтор. Ожидается сохранение ожидания до достоверного штатного опроса. Сценарий касается восстановления архивных ответов без явной связи.
