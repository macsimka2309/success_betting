# Приёмка исправлений третьего раунда

Изменение `add-alert-reminder-and-post-signal-goals` проверено локально на одноразовом PostgreSQL 16, подменённом Telegram и обезличенных спортивных фикстурах Chromium. [Исходный отчёт](../signal-tracking-review-round-3-2026-11-19/review.md)

| Сценарий | Результат |
|---|---|
| На 70-й минуте триггер ложный, на 75-й истинный, отправщик видит оба опроса | Бот закрывает ожидание по первому отрицательному наблюдению. Проверено для API-Football и Fonbet, в том числе после перезапуска |
| Архивный опрос сделан на минуте ниже уже сохранённой в снимке 75 | Опрос участвует в решении. Срез 75 сохраняет свою прежнюю политику выбора |
| Первый запрос начался до сигнала либо дал ошибку или неопределённый результат | Решение фиксируется по следующему допустимому определимому наблюдению. Устаревший положительный результат требует свежего подтверждения для отправки |
| В целостном live-таймлайне одна команда забивает на 90+2 и 90+6 | Аналитика сохраняет два разных ID. Повторное чтение сохраняет эти ID. Полный результат с отменой VAR исключает только отменённый гол |
| Суточная или первичная проверка делит один слот с матчем в концовке | Исходный срок переживает перенос и перезапуск. Просроченная задача получает штатный слот. В промежуточную минуту продолжает работать концовка |
| Блокировка браузера препятствует приоритетному чтению | Счётчики не растут. В следующем штатном цикле задача сохраняет возраст и порядок |
| Миграция 036 применяется к действующей очереди | Достоверные сроки восстанавливаются. При нехватке данных видно использование прежнего времени допуска. Закрытые состояния и история сохранены |

Для API-архива, созданного до миграции 036, учитываются записи с подтверждённой связью контекста и статистики. Новые штатные опросы сохраняют такую связь даже при неизменном снимке 75. Дополнительных сетевых запросов для восстановления связей не требуется.
