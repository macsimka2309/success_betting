# Русский SDD-каркас для Claude Code

Готовая структура нового проекта для разработки по методологии Spec-Driven Development: требования и спецификации сначала, реализация и проверка — после согласования.

## Быстрый старт

1. Распакуйте архив и переименуйте каталог проекта.
2. Инициализируйте Git: `git init`.
3. Откройте каталог в Claude Code.
4. Заполните документы последовательно, начиная с `docs/00-контекст-проекта.md`.
5. Не подключайте Claude к production-серверу до согласования инфраструктуры и плана реализации.

## Первый запрос Claude Code

```text
Мы начинаем новый проект и будем разрабатывать его строго по методологии Spec-Driven Development.

Прочитай CLAUDE.md.

На данном этапе ничего не устанавливай, не изменяй на сервере и не пиши production-код.

Твоя задача — помочь мне сформировать спецификацию проекта.

Работаем последовательно:
1. Определяем контекст и цели проекта.
2. Формируем функциональные требования.
3. Формируем нефункциональные требования.
4. Проектируем архитектуру.
5. Проектируем модель данных.
6. Проектируем инфраструктуру.
7. Определяем требования безопасности.
8. Только после этого формируем план реализации.

Не принимай существенные продуктовые и архитектурные решения молча. Если существует несколько разумных вариантов, покажи варианты, объясни плюсы и минусы, дай техническую рекомендацию и дождись моего выбора.

Начни с анализа задачи и формирования файла docs/00-контекст-проекта.md. После его согласования перейдём к требованиям.
```

## Запрос для безопасного аудита сервера

```text
Ты подключён к production-серверу. Перед любыми изменениями проведи аудит текущего состояния.

На первом этапе разрешены только безопасные операции чтения и диагностики. Не устанавливай пакеты, не меняй конфигурацию, не перезапускай сервисы, не изменяй firewall или SSH, не создавай и не удаляй Docker volumes, не изменяй базы данных.

Проверь ОС и версию, CPU, RAM, диски и свободное место, Docker и Docker Compose, запущенные контейнеры, открытые порты, firewall, существующие БД, reverse proxy, структуру каталогов и механизмы резервного копирования.

После аудита:
1. Сравни состояние с docs/04-инфраструктура.md.
2. Перечисли проблемы.
3. Предложи конкретный план изменений.
4. Оцени риски каждого изменения.
5. Ничего не меняй до моего явного одобрения плана.
```
