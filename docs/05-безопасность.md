# Безопасность

## Принципы

- минимально необходимые права;
- многоуровневая защита;
- безопасные настройки по умолчанию;
- явное подтверждение разрушительных действий;
- секреты не хранятся в репозитории.

## Модель угроз

Описать защищаемые данные, доверенные границы, потенциальных нарушителей и основные сценарии атак.

## SSH

Использовать ключи. Отключать парольный вход и root-доступ только после проверки рабочего альтернативного доступа.

## PostgreSQL

- отдельный пользователь приложения;
- приложение не использует суперпользователя;
- сетевой доступ ограничен;
- TLS применяется, если соединение проходит через недоверенную сеть;
- права выдаются на минимально необходимом уровне.

## Секреты

Использовать переменные окружения или менеджер секретов. `.env` не коммитить; `.env.example` не должен содержать настоящих значений. Определить правила ротации и отзыва.

## Web и API

- HTTPS;
- безопасные заголовки;
- валидация входных данных;
- контроль доступа;
- rate limiting для чувствительных операций;
- безопасное хранение паролей.

## Резервные копии

Backup должен быть автоматическим, регулярным, шифрованным при необходимости, проверяемым и храниться отдельно от production-БД.

## Логи и персональные данные

Не логировать пароли, access/refresh tokens, API keys, connection strings и лишние персональные данные. Определить срок хранения и доступ к логам.

## Реагирование на инциденты

Контакты, порядок изоляции, ротации секретов, восстановления, анализа и документирования.
