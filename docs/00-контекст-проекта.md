# Контекст проекта

## Название

Success Betting — хранилище и ежедневный сбор футбольных данных.

## Цель

Система ежедневно забирает данные о футбольных матчах из API-Football и хранит их
в PostgreSQL на собственном сервере. Хранилище заменяет текущий набор parquet-файлов
на локальном ноутбуке и служит единым источником данных для ML-моделей,
предсказывающих исход матча и тоталы голов.

Результат считается успешным, если:

- сбор данных идёт на сервере по расписанию, без запуска вручную с ноутбука;
- данные за каждый прошедший день попадают в базу не позднее следующего дня;
- повторный запуск сбора не создаёт дублей и не теряет ранее собранные данные;
- модель читает данные из базы, а не из файлов.

## Пользователи и заинтересованные стороны

Владелец проекта — единственный пользователь. Он же принимает продуктовые
и архитектурные решения. Внешних пользователей и публичного интерфейса нет.

## Основные сценарии

1. Ежедневный автоматический сбор: свежие матчи, результаты, события, статистика,
   составы и травмы записываются в базу по расписанию.
2. Первичный перенос: накопленные ранее данные из parquet-файлов проекта
   `download_football` загружаются в базу один раз.
3. Чтение для модели: пайплайн обучения и предсказания берёт выборки из базы.
4. Диагностика: владелец проверяет, за какие даты и лиги данные собраны,
   а где остались пропуски.

## Технологический стек

- Backend: Python 3 (скрипты сбора и загрузки, без веб-сервиса).
- Frontend: отсутствует.
- База данных: PostgreSQL 17 в Docker-контейнере.
- Инфраструктура: выделенный сервер Ubuntu 24.04, Docker Compose, cron.
- Развёртывание: вручную по SSH, автоматического CI/CD нет.

Детали зафиксированы в `docs/04-инфраструктура.md`.

## Ограничения

- Ресурсы сервера: 4 ГБ RAM, 100 ГБ диска, часть которых занята сторонним
  приложением; сервер общий, не выделен под этот проект целиком.
- Лимит внешнего API: тариф API-Football ограничивает число запросов в сутки,
  поэтому сбор обязан быть экономным и возобновляемым после сбоя.
- Безопасность: пароль базы и ключ API не попадают в Git; база не доступна
  из интернета.
- Персональные данные: не обрабатываются. Имена футболистов — публичная
  спортивная информация.
- Бюджет и сроки: жёстких сроков нет, работа ведётся владельцем в одиночку.
- Производительность: требований к задержке нет, сбор фоновый.

## Внешние системы

- **API-Football** (`v3.football.api-sports.io`) — основной источник: лиги, матчи,
  события, статистика, составы, травмы. Доступ по ключу, лимит запросов в сутки.
- **football-data.co.uk** — исторические результаты и коэффициенты букмекеров.
  Используется существующим проектом; включение в базу решается отдельно.
- **understat.com** — xG по пяти топ-лигам. Статус тот же.
