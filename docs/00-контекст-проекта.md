# Контекст проекта

## Название

Success Betting — хранилище и ежедневный сбор футбольных данных.

## Цель

Система ежедневно забирает данные о футбольных матчах из API-Football и хранит их
в PostgreSQL на собственном сервере. Задача этого этапа — накопить полную
и достоверную статистику матчей в одном хранилище. Хранилище заменяет текущий
набор parquet-файлов на локальном ноутбуке.

**Уточнено 28.09.2026.** Данные используются для обучения модели, предсказывающей
исход матча по семи рынкам: П1/X/П2, ТБ/ТМ (линия — скользящее среднее по
лиге), ОЗ/нОЗ, ИТБ/ИТМ (линия — скользящее среднее по команде), фора
(динамическая линия) и непроигрыш (двойной шанс). Сама схема хранения
(`docs/03`) при этом не меняется: признаки строятся отдельной материализованной
таблицей поверх сырых данных (ADR-8), не изменяя их (ADR-4).

Результат считается успешным, если:

- сбор данных идёт на сервере по расписанию, без запуска вручную с ноутбука;
- данные за каждый прошедший день попадают в базу не позднее следующего дня;
- повторный запуск сбора не создаёт дублей и не теряет ранее собранные данные;
- по данным в базе видно, за какие лиги и даты сбор выполнен полностью.

## Пользователи и заинтересованные стороны

Владелец проекта — единственный пользователь. Он же принимает продуктовые
и архитектурные решения. Внешних пользователей и публичного интерфейса нет.

## Основные сценарии

1. Ежедневный автоматический сбор: свежие матчи, результаты, события, статистика,
   составы и травмы записываются в базу по расписанию.
2. Первичный перенос: накопленные ранее данные из parquet-файлов проекта
   `download_football` загружаются в базу один раз.
3. Чтение данных: владелец выполняет произвольные SQL-запросы к базе
   для анализа накопленной статистики.
5. Обучение модели: таблица признаков `ml_match_features`
   (`specs/препроцессинг-для-модели.md`) служит источником для обучения
   и последующей оценки против рыночных коэффициентов.
4. Диагностика: владелец проверяет, за какие даты и лиги данные собраны,
   а где остались пропуски.

## Технологический стек

- Backend: Python 3 (скрипты сбора и загрузки, без веб-сервиса).
- Frontend: отсутствует.
- База данных: PostgreSQL 17 в Docker-контейнере.
- Инфраструктура: выделенный сервер Ubuntu 24.04, Docker Compose, cron.
- Развёртывание: вручную по SSH, автоматического CI/CD нет.

Детали зафиксированы в `docs/04-инфраструктура.md`.

## Ограничения

- Ресурсы сервера: 4 ГБ RAM, 100 ГБ диска, часть которых занята сторонним
  приложением; сервер общий, не выделен под этот проект целиком.
- Лимит внешнего API: тариф API-Football ограничивает число запросов в сутки,
  поэтому сбор обязан быть экономным и возобновляемым после сбоя.
- Безопасность: пароль базы и ключ API не попадают в Git; база не доступна
  из интернета.
- Персональные данные: не обрабатываются. Имена футболистов — публичная
  спортивная информация.
- Бюджет и сроки: жёстких сроков нет, работа ведётся владельцем в одиночку.
- Производительность: требований к задержке нет, сбор фоновый.

## Внешние системы

**API-Football** (`v3.football.api-sports.io`) — единственный источник данных
проекта: лиги, матчи, события, статистика матча (включая xG), составы, травмы
и коэффициенты букмекеров. Доступ по ключу, лимит запросов в сутки.

Другие источники не используются. Прежний проект брал результаты и коэффициенты
с football-data.co.uk, а xG с understat.com; здесь от них отказываемся в пользу
одного источника с единым форматом и идентификаторами.

## Текущий статус

Стадия проектирования. Документация заполняется, кода в репозитории нет.

Фактически сделано до введения SDD-процесса:

- на сервере поднят контейнер PostgreSQL 17 с ежедневным резервным копированием;
- база пустая, таблицы не создавались, миграций нет;
- скрипты сбора из проекта `download_football` скопированы в `scripts/legacy/`
  как справочный материал и пока не адаптированы.

Объём данных, накопленный в parquet и подлежащий переносу:

| Набор | Строк | Описание |
|---|---:|---|
| leagues_catalog | 1 239 | каталог лиг API-Football |
| fixtures | 1 092 857 | матчи с результатом и статусом |
| events | 2 711 817 | события матчей: голы, карточки, замены |
| statistics | 267 598 | статистика команды в матче, включая xG |

Данные покрывают 782 лиги, сезоны с 2018 по 2027 год.

**Наборы собраны неравномерно — сбор прерывался.** Матчи и результаты есть
по 22.09.2026, события — только по 21.07.2026, статистика — по 08.07.2026.
Около 25 300 завершённых матчей остались без событий и статистики.
Дозагрузка этого периода — требование ФТ-11.

Составы, травмы и коэффициенты ранее не выгружались. Составы и травмы
скрипт `scripts/legacy/download_apifootball.py` умеет забирать, кода для
коэффициентов в нём нет — его предстоит написать. Все три набора входят
в ежедневный сбор.
