# Модель данных

Схема повторяет структуру источника (ADR-4). Ключи — идентификаторы
API-Football (ADR-5). Требования — в `docs/01-требования.md`.

## СУБД

PostgreSQL 17. Одна схема `public`, отдельных схем не заводим.

## Общие правила

- у каждой таблицы есть первичный ключ;
- связи оформлены внешними ключами; удаление родителя запрещено (`ON DELETE RESTRICT`),
  чтобы случайная чистка справочника не унесла данные матчей;
- все отметки времени — `TIMESTAMPTZ`, хранятся и задаются в UTC (ФТ-2);
- все изменения схемы — только миграциями (ADR-7);
- каждая таблица имеет `fetched_at` — когда строка записана или обновлена;
  это позволяет отличить свежие данные от давно не обновлявшихся;
- запись идёт через `INSERT ... ON CONFLICT DO UPDATE`: повторный сбор
  обновляет строку, а не создаёт дубль (ФТ-3);
- денормализованные копии названий (команда, лига) в таблицах фактов
  не хранятся — они берутся из справочников.

## Состав таблиц

Справочники: `leagues`, `league_seasons`, `teams`, `players`, `bookmakers`, `bet_types`.
Факты: `fixtures`, `fixture_events`, `fixture_statistics`, `fixture_lineups`,
`fixture_lineup_players`, `injuries`, `odds_snapshots`, `odds_values`.
Служебные: `schema_migrations`, `collection_runs`, `fixture_fetch_state`.

## Справочники

### leagues

Каталог лиг из `/leagues`. Источник — 1 239 записей.

| Поле | Тип | Обяз. | Ограничения | Описание |
|---|---|---:|---|---|
| league_id | INTEGER | да | PK | ID лиги в API |
| name | TEXT | да |  | Название |
| type | TEXT | нет |  | `League` или `Cup` |
| country | TEXT | нет |  | Страна |
| country_code | TEXT | нет |  | Код страны, для наднациональных турниров пуст |

запросы (ФТ-5).

| end_date | DATE | нет |  | Конец сезона |
| has_events | BOOLEAN | нет |  | Источник отдаёт события |
| has_statistics | BOOLEAN | нет |  | Источник отдаёт статистику |
| has_lineups | BOOLEAN | нет |  | Источник отдаёт составы |
| has_injuries | BOOLEAN | нет |  | Источник отдаёт травмы |
| has_odds | BOOLEAN | нет |  | Источник отдаёт коэффициенты |

Первичный ключ: `(league_id, season)`.

## Факты

### fixtures

Матч. Центральная таблица, 1 092 857 строк при переносе.

| Поле | Тип | Обяз. | Ограничения | Описание |
|---|---|---:|---|---|
| fixture_id | INTEGER | да | PK | ID матча в API |
| league_id | INTEGER | да | FK → leagues | Лига |
| season | INTEGER | да |  | Сезон |
| kickoff_at | TIMESTAMPTZ | да |  | Время начала, UTC |
| match_date | DATE | да |  | Дата матча (для выборок по дням) |
| round | TEXT | нет |  | Тур |
| status_short | TEXT | нет |  | Статус: `FT`, `NS`, `PST`, … |
| status_long | TEXT | нет |  | Расшифровка статуса |
| elapsed | SMALLINT | нет |  | Минута для идущих матчей |
| home_team_id | INTEGER | да | FK → teams | Хозяева |
| away_team_id | INTEGER | да | FK → teams | Гости |
| goals_home | SMALLINT | нет |  | Голы хозяев |
| goals_away | SMALLINT | нет |  | Голы гостей |
| ht_home | SMALLINT | нет |  | Голы хозяев к перерыву |
| ht_away | SMALLINT | нет |  | Голы гостей к перерыву |
| venue_name | TEXT | нет |  | Стадион |
| venue_city | TEXT | нет |  | Город |
| fetched_at | TIMESTAMPTZ | да |  | Время записи |

Индексы: `(match_date)`, `(league_id, season)`, `(status_short)`,

Счёт хранится как есть. Исход матча (победа, ничья) не хранится: это
производная величина, её считает запрос (ADR-4).

### fixture_events

Событие матча: гол, карточка, замена, VAR. 2 711 817 строк при переносе.

| Поле | Тип | Обяз. | Ограничения | Описание |
|---|---|---:|---|---|
| event_id | BIGSERIAL | да | PK | Внутренний ключ |
| fixture_id | INTEGER | да | FK → fixtures | Матч |
| team_id | INTEGER | нет | FK → teams | Команда |
| minute | SMALLINT | нет |  | Минута |
| minute_extra | SMALLINT | нет |  | Добавленное время |
| type | TEXT | да |  | `Goal`, `Card`, `subst`, `Var` |
| detail | TEXT | нет |  | Уточнение: `Normal Goal`, `Yellow Card`, … |
| player_id | INTEGER | нет | FK → players | Игрок |
| assist_player_id | INTEGER | нет | FK → players | Ассистент или заменяющий |
| comments | TEXT | нет |  | Комментарий источника |
| event_key | TEXT | да | UNIQUE | Ключ для защиты от дублей |
| fetched_at | TIMESTAMPTZ | да |  | Время записи |

**Особый случай.** У событий нет собственного идентификатора в API, поэтому
естественного ключа не существует. `event_key` — строка, собранная из
`fixture_id`, минуты, добавленного времени, команды, типа, уточнения и игрока.
Повторный разбор того же матча даёт тот же ключ и не создаёт дублей (ФТ-3).

Ограничение: два неразличимых события в одну минуту (например, два жёлтых
одному игроку на одной минуте) схлопнутся в одну строку. Случай редкий,
и потеря здесь безопаснее, чем дубли при каждом повторном разборе.

Индексы: `(fixture_id)`, `(player_id)`, `(type)`.

### fixture_statistics

Статистика одной команды в матче. 267 598 строк при переносе.

Первичный ключ: `(fixture_id, team_id)`.

Числовые поля (все `SMALLINT`, необязательные): `shots_on_goal`,
`shots_off_goal`, `total_shots`, `blocked_shots`, `shots_insidebox`,
`shots_outsidebox`, `fouls`, `corner_kicks`, `offsides`, `yellow_cards`,
`red_cards`, `goalkeeper_saves`, `total_passes`, `passes_accurate`,
`substitutions`, `free_kicks`, `assists`, `counter_attacks`, `cross_attacks`,
`goals`, `goal_attempts`, `throwins`, `medical_treatment`.

Отдельного разбора требуют четыре поля, которые источник отдаёт строками:

| Поле | Тип в базе | Источник | Преобразование |
|---|---|---|---|
| ball_possession | SMALLINT | `"58%"` | процент без знака |
| passes_pct | SMALLINT | `"84%"` | процент без знака |
| expected_goals | NUMERIC(5,2) | `"1.74"` | число |
| goals_prevented | NUMERIC(5,2) | `"0.31"` | число |

Приведение к числу выполняется при записи. Хранить проценты строками
означало бы невозможность сравнений и агрегатов в запросах.

Индексы: `(team_id)`.

### odds_snapshots

Снимок линии по матчу, два раза в сутки (ФТ-10). Разделение на снимок
и значения избавляет от хранения времени и матча в каждой из тысяч строк

| Поле | Тип | Обяз. | Ограничения | Описание |
|---|---|---:|---|---|
| snapshot_id | BIGSERIAL | да | PK | Внутренний ключ |

| taken_at | TIMESTAMPTZ | да |  | Время снимка (наше) |
| source_updated_at | TIMESTAMPTZ | нет |  | Время обновления по данным API |
| fetched_at | TIMESTAMPTZ | да |  | Время записи |

### odds_values

Котировка: снимок, букмекер, рынок, исход.

| Поле | Тип | Обяз. | Ограничения | Описание |
|---|---|---:|---|---|
| snapshot_id | BIGINT | да | PK, FK → odds_snapshots | Снимок |
| bookmaker_id | INTEGER | да | PK, FK → bookmakers | Букмекер |
| bet_type_id | INTEGER | да | PK, FK → bet_types | Рынок |
| value | TEXT | да | PK | Исход: `Home`, `Over 2.5`, … |
| odd | NUMERIC(10,3) | да |  | Коэффициент |

Первичный ключ: `(snapshot_id, bookmaker_id, bet_type_id, value)`.

`value` остаётся строкой намеренно: у разных рынков это и `Home`, и `Over 2.5`,
и точный счёт `2:1`. Разбор на составляющие — производная операция (ADR-4).

**Самая быстрорастущая таблица.** Один снимок по матчу — около сотни строк
при двух букмекерах (1xBet до 82 рынков, Pinnacle 15; у рынка несколько
исходов). Оценка роста — в разделе «Объёмы и рост».

## Связи

- `leagues` 1 — N `league_seasons` 1 — N `fixtures`;
- `fixtures` 1 — N `fixture_events`, `fixture_statistics`, `fixture_lineups`,
  `injuries`, `odds_snapshots`;
- `fixture_lineups` 1 — N `fixture_lineup_players`;
- `odds_snapshots` 1 — N `odds_values`;
- `teams` и `players` — справочники, на них ссылаются таблицы фактов.

Удаление родительских строк запрещено. Исключение — `odds_snapshots`:
при удалении снимка его значения удаляются каскадом, иначе архивирование
старых котировок потребовало бы двух шагов.

## Политика удаления

- данные матчей, событий, статистики, составов и травм **не удаляются**;
- исправления приходят обновлением строки (ФТ-3);
- котировки старше срока хранения могут архивироваться или удаляться —
  решение отложено до появления реальных объёмов;
- «мягкого удаления» (пометки вместо удаления) нет: данные не удаляются вовсе.

## Миграции

- инструмент: нумерованные SQL-файлы и собственный скрипт применения (ADR-7);
- именование: `NNN_краткое_описание.sql`, например `001_initial_schema.sql`;
- откат: отдельный файл `NNN_краткое_описание.down.sql`;
- порядок: по возрастанию номера, применённые отмечаются в `schema_migrations`;
- обратная совместимость: новые поля добавляются необязательными; удаление
  и смена типа поля выполняются отдельной миграцией после анализа.

## Объёмы и рост

| Таблица | Строк при переносе | Рост |
|---|---:|---|
| fixtures | 1 092 857 | ~137 000 в год |
| fixture_events | 2 711 817 | ~340 000 в год |
| fixture_statistics | 267 598 | ~270 000 в год |
| fixture_lineups | 0 | ~270 000 в год |
| fixture_lineup_players | 0 | ~5 млн в год |
| injuries | 0 | сотни тысяч в год |
| odds_values | 0 | **несколько миллионов в год** |

Первые шесть таблиц роста не создают проблем. `odds_values` требует
наблюдения: два снимка в сутки по матчам с линией дают порядка нескольких
миллионов строк в год при двух букмекерах.

**Порядок действий:** после месяца работы измерить фактический объём
и вернуться к решению — сузить набор рынков, сократить частоту снимков
или архивировать старые котировки. Заранее ограничивать не будем: требование
ФТ-10 предписывает хранить всё, а реальные цифры сейчас неизвестны.
